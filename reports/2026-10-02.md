# 以太坊日报 2026-10-02

摘要：EF 与 Open Anonymity Project 发布 zkAPI，用零知识证明为付费 API 做匿名额度支付。soispoke 介绍 EIP-8288 下私密、抗量子的转账，Kassandra 主张把隐形地址做成所有钱包都能接入的最小接收标准。规范侧主要是 Glamsterdam 的 BAL（EIP-7928）和 Hegotá 候选 SETCODEFROM（EIP-8298）的细化。

## 今日要点
1. **zkAPI**：在以太坊 vault 里一次性存入额度，之后用零知识证明授权有上限的调用，API 提供方看到请求、支付层看到花费，两者都无法把请求和身份关联起来。
2. **EIP-8288 隐私转账**：soispoke 展示 EIP-8288 下私密且抗量子的转账。
3. **隐形地址做最小标准**：Kassandra 认为大家先统一一个简单的私密收款标准，各钱包再自行决定如何管理隐私。
4. **规范细化**：Glamsterdam 的 EIP-7928 BAL 多处澄清合并；Hegotá 候选 EIP-8298 改为在 BAL 中记录被复用代码的哈希。

## 重点话题

### 1. 隐私支付：zkAPI 与 EIP-8288
**发生了什么**
- [EF 博客：zkAPI，给任意 API 的私密用量额度](https://blog.ethereum.org/en/2026/10/01/introducing-zkapi)，EF 03:14 在 X 宣布（[@ethereumfndn 推文](https://x.com/ethereumfndn/status/2105753290977980682)）。用法是往以太坊 vault 存一次额度，再用零知识证明代替身份去授权有上限的用量。文中的例子是私密 AI 推理。
- [soispoke：EIP-8288 下私密、抗量子的转账](https://x.com/soispoke/status/2106055901446549680) 23:17。
- [Kassandra：隐形地址应是所有钱包都能采用的最小标准](https://x.com/kassandraETH/status/2106056728353620188) 23:20，统一的是“私密收款”这一步，其余隐私管理交给各钱包。

**为什么重要**
- zkAPI 把“按量付费”和“身份”拆开，对用户是不用注册账号就能买 API 额度；对开发者，它提供了一个用以太坊做匿名计费的现成模式。隐形地址如果收敛成最小公共标准，钱包接入私密收款的成本会大幅下降。

### 2. BAL（Glamsterdam）与 SETCODEFROM（Hegotá 候选）细化
**发生了什么**
- [EIP-8298：在 BAL 中以哈希记录被采用的代码，拒绝同一交易内创建的源](https://github.com/ethereum/EIPs/pull/12399) 合并（CPerezz）。
- EIP-7928（区块级访问列表）三处澄清合并：[storage key 排序](https://github.com/ethereum/EIPs/pull/12415)（nerolation）、[空 BAL 的条件](https://github.com/ethereum/EIPs/pull/12416) 和 [warm `SELFDESTRUCT` 受益人访问成本](https://github.com/ethereum/EIPs/pull/12408)（colinlyguo）。
- [EIP-8159 对齐 EIP-7928 的 BAL 存储类型](https://github.com/ethereum/EIPs/pull/12397) 合并。

**为什么重要**
- SETCODEFROM 让账户复用已有代码，和 7702 委托一样直接影响账户代码来源；BAL 记录哈希意味着并行验证时也能确定代码来源。BAL 已随 Glamsterdam 进入测试网阶段，合约和钱包开发者应开始对照规范测试；SETCODEFROM 仍是 Hegotá 草案，可以参与讨论。
