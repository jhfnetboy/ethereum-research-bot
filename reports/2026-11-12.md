## 今日要点
1. Ethlabs 发布 pqai27：提议以太坊在 2027 年做到“后量子 + 后 AI 就绪”，Hegotá 执行层优先上线带 SPHINCS 后量子签名的 Frames 和后量子账户 EIP，FOCIL 不应拖慢这个目标，Ethlabs 撤回 Hegotá 中的 quick slots。

## 重点话题

### 1. pqai27：Ethlabs 提议 2027 年完成后量子与后 AI 加固
**发生了什么**
- [Ethlabs：An Ethlabs view on post-quantum and post-AI timelines: pqai27](https://ethereum-magicians.org/t/an-ethlabs-view-on-post-quantum-and-post-ai-timelines-pqai27/30351) 2026-11-12 03:51 发布于 Magicians。核心主张：以太坊应在 2027 年达到 pqai-ready，即共识层后量子化、每个用户的账户都有后量子迁移路径，同时保持 Glamsterdam 带来的扩容容量；pqai-scaled（后量子交易和 blob 满容量运行）是 2027 年的延伸目标。
- 文中给出的 Hegotá 草案：执行层上线 Frames + SPHINCS 后量子签名 + 后量子账户 EIP，且在没有 FOCIL 的情况下可以不等共识层单独上线；共识层开始做后量子共识（后量子版 Gasper 或 decoupled consensus，尚未决定）。之后的 I 升级再做后量子 DA（EIP-8479）和签名聚合（EIP-8288），可能把 FOCIL 一起带上。（同一来源，2026-11-12）
- 文中写明 Glamsterdam 按计划推进，Frames 在 pqai27 的关键路径上；Ethlabs 撤回 Hegotá 中的 quick slots，转向 2028 年再推更快的 slot。（同一来源，2026-11-12）
- [Ethlabs 在 X 上发布 pqai27](https://x.com/ethlabs_org/status/2120621682889052345) 2026-11-12 03:56，说明这是给以太坊治理流程的输入。
- [Barnabé：重新排序意味着放弃一些我们珍视的提案](https://x.com/barnabemonnot/status/2120633537464316150) 2026-11-12 04:43，指出后量子工作本身也会带来新的 pq-ready 账户（基于 Frame Transactions）。
- [Caspar 在 ACDC #191 议程中申请讨论 pqai27](https://github.com/ethereum/pm/issues/2291) 2026-11-12 06:49 留言。

**为什么重要**
- 对你关注的账户方向是直接利好：Frames（EIP-8141）在这个方案里从“Hegotá headliner 之一”变成“必须先上的关键路径”，后量子账户迁移会成为钱包和 AA 生态的主线工作。文中还点名了借机推广的账户能力：密钥轮换、恢复密钥和执行密钥分离、按范围授权。
- 代价也很明确：FOCIL（抗审查）和 quick slots（更快出块）会被推后，Hegotá 的范围可能大改。
- 用户层面，pqai-ready 之后后量子交易可用，但因为签名更大，成本会更高，要等 pqai-scaled 和签名聚合才能接近普通交易成本。（来源同上）

**接下来关注**
- 今晚 21:00 ACDC #191 上核心开发者的第一反应，以及是否有客户端团队公开支持或反对把 FOCIL 让路。
- 后量子共识选 Gasper 改造还是 decoupled consensus，提案里说这是最大的未决问题。
- 钱包和 AA 团队是否开始规划基于 Frames 的后量子账户迁移工具。

### 2. 账户抽象与交易：Frames 生态的 EIP 一夜四改
**发生了什么**
- [EIP-8141 补充：SENDER frame 何时让交易在执行前就无效](https://github.com/ethereum/EIPs/pull/12656) 2026-11-12 07:12 提交：只有带 APPROVE_EXECUTION 标志的 frame 能设置 sender_approved，所以前面没有这种 frame 的 SENDER frame 一定失败，builder 和 mempool 可以不执行就丢弃。
- [EIP-8250 更新：一次性 keyed 交易可通过静态和 mempool 检查](https://github.com/ethereum/EIPs/pull/12659) 2026-11-12 07:12 提交：nonce_seq 等于 MAX_NONCE_SEQ 且所选 key 都为 0 时视为可执行，不算 nonce 溢出；重放保护不变。
- [EIP-8151 更新：为 recovered signer 增加公共 mempool 规则](https://github.com/ethereum/EIPs/pull/12653) 2026-11-12 01:20 提交：在 EIP-8151 下 ecRecover 会读取恢复地址的代码，EIP-8141 的验证前缀因此可能依赖第三方账户，这个 PR 补上对应的 mempool 规则。
- [EIP-8288 更新：批量处理通用签名声明](https://github.com/ethereum/EIPs/pull/12654) 2026-11-12 04:49 提交：允许一个用户选择的批处理程序为多笔交易、多种签名方案一起出证明；PR 中给出的成本是每个声明 30,000 intrinsic proof-share gas 加 3,000 验证 gas。
- [EIP-8288 更新：dependency triple 使用 EIP-8141 的 leanSPHINCS scheme id](https://github.com/ethereum/EIPs/pull/12657) 2026-11-12 07:12 提交，让同一个 leanSPHINCS 密钥在两个 EIP 里用同一个编号（目前是 0x3）。
- [新 EIP 草案：eth/73 证明封装传播](https://github.com/ethereum/EIPs/pull/12655) 2026-11-12 04:50 提交，基于 EIP-8288，允许把原始签名直接提交给聚合者，不必先生成 STARK。

**为什么重要**
- 这些都是 pqai27 关键路径上的具体规范工作：EIP-8141 是 Frames 本体，EIP-8288 是后量子签名聚合，二者的 SPHINCS 编号统一说明两个规范正在对齐。
- mempool 规则（EIP-8141、EIP-8151、EIP-8250）决定智能账户交易能不能在公共 mempool 安全传播，这是原生 AA 落地前最容易被低估的部分。

**接下来关注**
- 11/17 的 Frame Transaction Breakout #8（[pm #2295](https://github.com/ethereum/pm/issues/2295)），以及 pqai27 是否让 Frames 的范围变化（提案提到可能有更轻量的 Frames 变体）。

### 3. 基础设施：BAL 加入 code read，弹性容量的新思路
**发生了什么**
- [新 EIP 草案：Code Reads in Block-Level Access Lists](https://github.com/ethereum/EIPs/pull/12658) 2026-11-12 07:12 由 LukaszRozmej 提交：在 EIP-7928 的 AccountChanges 中加入 code_hash，这样 BAL 能列出区块读取的全部区块前状态，无状态客户端或证明者只用区块、BAL 和状态快照就能组装输入，不必先执行区块。对应的 [Magicians 讨论帖](https://ethereum-magicians.org/t/code-reads-in-block-level-access-lists-extension-to-eip-7928/30354) 于 2026-11-12 07:14 开启。
- [ethresear.ch：Elastic Ethereum](https://ethresear.ch/t/elastic-ethereum/26236) 2026-11-11 18:40 由 cskiraly 发布的观点帖：主张按测得的资源压力动态调整容量，像 TCP 拥塞控制那样，而不是固定 gas 上限加安全余量。文中引用主网数据称，区块中位数在首次被看到后 0.38 秒到达 95% 的上报节点（99 分位区块为 0.70 秒）。

**为什么重要**
- BAL 是 Glamsterdam 的核心改动之一，补上 code read 能让无状态验证和 zk 证明更方便，与 gas 上限提升直接相关。
- 弹性容量是对“gas 上限怎么定”的另一种思路，目前只是研究观点，没有对应 EIP。

**接下来关注**
- code read 扩展是否会被提议并入 Glamsterdam 的 EIP-7928。
