## 今日要点
1. **7702 授权加有效期**：EIP-8477 让每个委托授权签入一个最近区块号和区块哈希，只在之后 256 个区块内有效，防止授权被长期保存再回放。
2. **Frame Transaction 为 PQ 签名腾空间**：加入 lean SPHINCS；把签名数据的 calldata 成本排除出 100k 的 MAX_VERIFY_GAS，否则 PQ 签名光凭体积就超限。
3. **Glamsterdam 规范勘误**：同一时间提交 7 个 PR，修正 EIP-2780 委托目标预热规则、EIP-8037/8038 的错误表述等，不改 gas 规则。
4. Devcon 第 2 天：ETHBEAT 上线，EEZ 演示 rollup 与主网的同步可组合，Quicknode 支持 FCR。

## 重点话题

### 1. EIP-8477：带新鲜度的 7702 委托授权
**发生了什么**
- [EIP-8477 Recent Block Bound Delegation Authorizations 讨论帖](https://ethereum-magicians.org/t/eip-8477-recent-block-bound-delegation-authorizations/30269) 00:39 开帖（作者 dangerousfood），动机直接写的是 Binance 事件中的 7702 清扫。每个授权除了链 ID、委托地址和 nonce，还要签入一个最近的执行区块号和区块头哈希。被包含进区块 N 时，签入的区块必须是 N 之前 256 个祖先之一且哈希匹配；正好 256 个区块前仍有效，257 个就失效，当前和未来区块都不行。新鲜度在签名恢复之前检查，过期或不匹配的授权直接跳过。

**为什么重要**
- 今天的 7702 授权可以先签好、过很久再上链。EIP-8477 把授权的有效窗口压到约 51 分钟（256 个 12 秒 slot），被盗签名服务事先囤积的授权就没法用。代价是授权必须临近使用时签，离线签名、硬件钱包预签、赞助方代发的流程都要调整。
- 和 EIP-8476（永久退出委托）配合看：一个限制授权“什么时候能用”，一个让账户“永远不再接受授权”。

**接下来关注**
- 钱包和 4337/7702 赞助服务对 256 区块窗口的反馈；是否提交为正式 PR。

### 2. EIP-8141 Frame Transaction：为后量子签名调整验证预算
**发生了什么**
- [EIPs PR #12616：Update EIP-8141 add lean sphincs](https://github.com/ethereum/EIPs/pull/12616) 12:26 由 lightclient 提交，把 lean SPHINCS（基于哈希的后量子签名）加进 frame transaction 的签名方案。
- [EIPs PR #12617：EIP-8141 不把 calldata 成本算进 MAX_VERIFY_GAS](https://github.com/ethereum/EIPs/pull/12617) 15:59 由 nerolation 提交。内存池规则 6 原文“验证 `tx.signatures` 的固有成本”可能被理解为包含签名字节的 calldata 成本。修订改为 `signature_verification_cost`，并写明 `frame_data_cost`、`signature_data_cost` 不计入。理由：MAX_VERIFY_GAS 限制的是节点验证工作量，calldata 成本付的是带宽和区块空间；如果计入，PQ 签名光凭体积就会超过 10 万的上限。
- [Frame Transaction Breakout #8 定于 11 月 17 日](https://github.com/ethereum/pm/issues/2295) 17:17 建立议程（[Magicians 公告](https://ethereum-magicians.org/t/frame-transaction-breakout-8-nov-17-2026/30274)）。

**为什么重要**
- 原生 AA 的验证帧是“未付费”的计算，MAX_VERIFY_GAS 决定账户能用多复杂的签名。这两处修订让 PQ 账户在 frame transaction 里可行，是“AA 是 PQ 账户迁移基础”的具体落地。

### 3. Glamsterdam 规范勘误：EIP-2780、EIP-8037、EIP-8038 等
**发生了什么**
- flcl42 在 21:26 同时提交 7 个非作者修订：[EIPs PR #12622：EIP-2780 修正 floor 引用并写明委托目标预热规则](https://github.com/ethereum/EIPs/pull/12622)（Glamsterdam 中 floor 用 EIP-7976 的 `floor_tokens_in_calldata`，每字节 4 个 token、每 token 16 gas，加 EIP-7981 访问列表数据附加费；execution-specs 已按修正后的文字实现）、[EIPs PR #12624：EIP-8037 修正与规范矛盾的表述](https://github.com/ethereum/EIPs/pull/12624)、[EIPs PR #12626：EIP-8038 限定 ACCOUNT_WRITE 规则与最坏情况客户端说法](https://github.com/ethereum/EIPs/pull/12626)、[EIPs PR #12623：EIP-7708 修正 gas 数字与创建交易规则](https://github.com/ethereum/EIPs/pull/12623)、[EIPs PR #12625：EIP-7778 删除矛盾的恢复原值折扣示例](https://github.com/ethereum/EIPs/pull/12625)，以及 EIP-7928、EIP-7843 各一处。

**为什么重要**
- EIP-2780（按资源计价的交易固有 gas）、EIP-8037（状态创建涨价）、EIP-8038（状态访问调价）都是 Glamsterdam 中直接影响每笔交易成本的改动，目前都在 Last Call。文字和实现不一致会让合约开发者按错误数字估算 gas。
