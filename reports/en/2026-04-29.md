## Key topics

### 1. Native AA: EIP-8141 and EIP-8130
**What happened**
- [EIP-8141: allow payer to approve before sender](https://github.com/ethereum/EIPs/pull/11575) (lightclient), submitted and merged: an alternative to the #11555 guarantor role, which the author finds simpler; it was meant to be a draft, so [#11579](https://github.com/ethereum/EIPs/pull/11579) reverted it (submitted and merged) and [#11580](https://github.com/ethereum/EIPs/pull/11580) resubmitted it.
- [EIP-8141: remove the RLP call batch for the default account](https://github.com/ethereum/EIPs/pull/11577) (lightclient), submitted and merged: with frame batching, the default account no longer needs RLP call batches.
- [EIP-8130: add an opaque_input bytes field](https://github.com/ethereum/EIPs/pull/11578) (pochenai), submitted: restores the transaction level metadata role of the legacy input field (such as ERC-8021 attribution suffixes) in AA transactions; it is not part of EVM execution but must be in both the sender and payer signature hashes so relayers and builders cannot swap it.

**Why it matters**
- For accounts: letting the sponsor approve first supports paymaster style flows without a new role and keeps the spec smaller; dropping a duplicate batching mechanism from the default account means fewer branches for clients.
- For transactions: because opaque_input is signed, intermediaries cannot tamper with attribution data.

### 2. Post-quantum: upgrading an EOA in one transaction
**What happened**
- [ethresear.ch: upgrade any Ethereum wallet to post-quantum security in one transaction using ZK proofs with a hidden public key](https://ethresear.ch/t/upgrade-any-ethereum-wallet-to-post-quantum-security-in-one-transaction-using-zk-proofs-with-a-hidden-public-key/24754), 18:07: the EOA delegates via EIP-7702 to a contract that only accepts ZK proofs of ECDSA knowledge under a hidden public key, with no address change, no asset migration and no consensus change; 87 ms to prove, 65 ms to verify and a 226 KB proof on Apple M1.
- [PQ Interop #37 agenda](https://ethereum-magicians.org/t/post-quantum-pq-interop-37-april-29-2026/28392), 02:48.

**Why it matters**
- For accounts: EOAs that have transacted already expose their public key onchain; this offers a transition path without protocol changes, though every transaction pays for proof verification.
