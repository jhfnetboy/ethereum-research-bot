# Ethereum Research Daily 2026-09-30

Keywords: EIP-8430 discussion thread, EIP-8298 records code hashes in the BAL, EF post-quantum hash-based signature challenge, ethrex v28 ready for Glamsterdam, Glamsterdam risk and governance debate

Summary: EIP-8430 (the AA transaction type split out of 8130) opened its discussion thread, explaining the split: the transaction type is useful on its own and can ship first. EIP-8298 submitted a revision (merged October 2) so `SETCODEFROM` records only the code hash in the BAL and rejects sources created in the same transaction, preventing one 9,300 gas call from adding up to 24 KiB to the BAL. The EF launched an open challenge to design stateless hash-based signatures for post-quantum Ethereum and prove them secure in Lean.

## Highlights
1. **EIP-8430**: works for today's EOAs and can ship before the Keystore.
2. **BAL size**: if SETCODEFROM recorded full bytecode, one call could add up to 24 KiB to the BAL.
3. **Post-quantum signatures**: the EF's autoresearch challenge competes on signature size times verification cycles.
4. **Glamsterdam readiness**: ethrex v28.0.0 is listed alongside every other execution client in an EF upgrade announcement for the first time.

## Key topics

### 1. State costs for accounts and code
**What happened**
- [Magicians: EIP-8430 AA transaction type (split out from 8130)](https://ethereum-magicians.org/t/eip-8430-aa-transaction-type-split-out-from-8130/29810), 19:00 (chunter); the transaction type has no Keystore dependency and works for today's EOAs with native secp256k1 authentication, so it can ship first and the Keystore can follow.
- [EIP-8298: record adopted code as a hash in the BAL and reject same-transaction-created sources](https://github.com/ethereum/EIPs/pull/12399) (CPerezz). EIP-7928 records every code hash change as full bytecode, so one warm-source `SETCODEFROM` at 9,300 gas could add up to 24 KiB to the BAL; a hash-only entry needs the bytecode findable elsewhere, and a source created and self-destructed in the same transaction would leave the hash with no bytecode anywhere.
- [EIP-8250: record activation state changes at block access index 0](https://github.com/ethereum/EIPs/pull/12406) (later closed); EIP-8250 and EIP-8272 install contracts in their first active block, and implementations disagreed on where that goes in the BAL.
- [EIP-8037: add Paweł Bylica as co-author](https://github.com/ethereum/EIPs/pull/12400), merged, along with two other PRs adding co-authors.

**Why it matters**
- Smart accounts rely on code reuse to cut deployment costs, but reuse must not let block data grow without bound. Gas prices and BAL size have to be considered together.
