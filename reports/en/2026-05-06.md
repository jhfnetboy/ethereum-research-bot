## Key topics

### 1. Native AA and signatures
**What happened**
- [EIP-8141: disable the EIP-3607 check for frame transactions](https://github.com/ethereum/EIPs/pull/11272) (Thegaram), merged.
- [Add EIP: Cryptographically Agile Transactions](https://github.com/ethereum/EIPs/pull/11413) (shemnon), merged: CATX uses a flat structure that separates the body from signatures, commits signatures by position to prevent key substitution and lets trailing signatures be stripped for ZK aggregation, so post-quantum migration does not change transaction semantics.
- [EIP-8130: add create entry existing account and code size guards](https://github.com/ethereum/EIPs/pull/11609) (pochenai), submitted: besides code_size(from) == 0, it now requires nonce(from) == 0 and no existing owner_config, so a create entry cannot be replayed against an EOA with history at the counterfactual address.

**Why it matters**
- For accounts: EIP-3607 rejects transactions from addresses with code, and frame transaction senders may be contracts, so disabling it is a precondition for native AA; CATX, like EIP-7932, prepares for post-quantum migration; the EIP-8130 fixes show the authorization and replay boundaries of AA transactions are still under close review.

### 2. Transactions and gas
**What happened**
- [EIP-8037: fix bugs from bal-devnet-6](https://github.com/ethereum/EIPs/pull/11611) (misilva73), submitted: for example refunding the new account part of intrinsic state gas when a contract creation transaction reverts; [EIP-8037: clarify SELFDESTRUCT charges](https://github.com/ethereum/EIPs/pull/11606) (misilva73), submitted and merged.
- [Add EIP: Cap Deposit Requests Per Block](https://github.com/ethereum/EIPs/pull/11607) (barnabasbusa), submitted; [Magicians: EIP-8254](https://ethereum-magicians.org/t/eip-8254-cap-deposit-requests-per-block/28453), 16:06.
- [Add EIP: Upgrade pre-Spurious-Dragon accounts](https://github.com/ethereum/EIPs/pull/11605) (jochem-brouwer), submitted; [EIP-8246: Remove SELFDESTRUCT Burn](https://github.com/ethereum/EIPs/pull/11590) (chfast), merged.

**Why it matters**
- For users: without the devnet refund fix, users whose contract deployment fails would overpay state gas.

### 3. Approval safety
**What happened**
- [Add ERC-8255: Expiring Token Approvals](https://github.com/ethereum/ERCs/pull/1721) (moodysalem), submitted: adds an expiration to ERC-20 allowances, so default approvals lapse after a token defined duration.

**Why it matters**
- For users: unlimited approvals are a common path to losses from phishing and contract bugs, and automatic expiry shrinks that window.
