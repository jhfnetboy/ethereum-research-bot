## Key topics

### 1. Post-quantum migration: bunker mode
**What happened**
- [Justin Drake: calling on the industry to calmly begin planning for bunker mode](https://x.com/drakefjustin/status/2107837081313505768), 21:14. His personal recommendation is a controlled mass migration of assets to fresh addresses whose public keys remain hidden behind a hash, with large holders going first.

**Why it matters**
- Once an EOA has sent a transaction, its public key is onchain; an address that has never sent one exposes only the hash of its key. For users, a fresh address is the cheapest defense until wallets support post-quantum signatures, though migration carries its own risk of sending to the wrong address. For the protocol, it puts frame transactions and crypto agility for accounts front and center, and Vitalik and binji both responded the next day.

### 2. Who cleans up the bytecode SETCODEFROM leaves behind
**What happened**
- [ethresear.ch: who cleans up the code? SETCODEFROM's dangling bytecode and futureproof design choices](https://ethresear.ch/t/who-cleans-up-the-code-setcodefroms-dangling-bytecode-and-futureproof-design-choices/26127), 04:00 (CPerezz). Clients already keep bytecode that no account points to; EIP-8058 counted 27,869 such entries on a full-synced node as of Cancun, harmless so far because code sits outside the state root. SETCODEFROM, proposed for Hegotá, gives every transaction a new way to leave code behind, and the partitioned binary tree (PBT) moves code inside the state root. Combined, full-synced and snap-synced nodes would disagree on what is in their code databases. The author argues for settling the rules while EIP-8298 is still a draft.
- [EIP-8250 PR: add nonce_type as a separate transaction field](https://github.com/ethereum/EIPs/pull/12441) (GottfriedHerold); [EIP-8272 PR: deploy the recent root contract as a standard contract](https://github.com/ethereum/EIPs/pull/12443).

**Why it matters**
- SETCODEFROM and 7702 both change where account code comes from. Once code is in the state root, the rules for reuse and cleanup affect state size and sync consistency, and through them the pricing of these operations.
