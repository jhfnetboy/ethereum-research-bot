## Key topics

### 1. Glamsterdam repricing: developers start measuring
**What happened**
- [pcaversaccio: Osaka vs Amsterdam gas for a simple CREATE2-deployed ERC-20](https://x.com/pcaversaccio/status/2110742093861724530), 21:38. The extra state gas EIP-8037 adds for the SSTOREs is 64×1,530=97,920 and shows up only in the Amsterdam CREATE2 line. [He also asked why EIP-7997 is planned for inclusion](https://x.com/pcaversaccio/status/2110754372397514809), 22:27; his CreateX factory is deployed on over 200 EVM chains with verifiably identical bytecode.
- [New EIP: net gas metering for account changes](https://github.com/ethereum/EIPs/pull/12058) and [persist warm access sets across reverts](https://github.com/ethereum/EIPs/pull/12128) were merged (rakita), along with [a contract storage layout descriptor format](https://github.com/ethereum/EIPs/pull/12247) (forshtat).
- [EIP-8038: expand the gas estimation methodology and add supporting reports](https://github.com/ethereum/EIPs/pull/12517) was merged (misilva73).

**Why it matters**
- More expensive state creation hits accounts most directly: deploying a contract wallet and writing storage for the first time both cost more. Wallets and factory contracts should re-measure deployment costs under Amsterdam rules and check hardcoded gas limits. EIP-7997 (a deterministic deployment factory) concerns same-address deployment across chains, so maintainers of existing factories like CreateX care whether it duplicates them.

### 2. Frame transactions: signer authority and nonces
**What happened**
- EIP-8141: [check signer key authority](https://github.com/ethereum/EIPs/pull/12505) (Marchhill), [set code from the default code in SENDER mode](https://github.com/ethereum/EIPs/pull/12506) and [price every data byte the same](https://github.com/ethereum/EIPs/pull/12512) (AnkushinDaniil).
- [EIP-8250: mark single-use keys with MAX_NONCE_SEQ](https://github.com/ethereum/EIPs/pull/12511) (nerolation).
- [EIP-8209: move COMMIT and REVEAL to free frame modes and use the EIP-8141 frame layout](https://github.com/ethereum/EIPs/pull/12509) was merged, as was [EIP-7906: state the POST_TX rollback point via the EIP-8141 validation prefix](https://github.com/ethereum/EIPs/pull/12516).
- [EIP-8288: add recursive_stark_gas to the calldata floor](https://github.com/ethereum/EIPs/pull/12510) and [reserve the zero data_hash for the signature hash](https://github.com/ethereum/EIPs/pull/12518).

**Why it matters**
- More and more EIPs (8209, 7906, 8288) reuse EIP-8141's frame layout directly, so frame transactions are becoming the shared base for new account and transaction features.
