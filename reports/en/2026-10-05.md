## Key topics

### 1. Native transaction assertions: constraining outcomes beyond the signature
**What happened**
- [EF Blog: how native transaction assertions could enforce a transaction's final outcome](https://blog.ethereum.org/en/2026/10/05/transaction-assertions). The post separates two failure modes. In an intent mismatch (Bybit, BadgerDAO), a compromised frontend supplied a signing request that differed from what users believed they were approving. In an outcome mismatch (the Aave and CoW collateral swap), a user swapped about $50.4 million of aEthUSDT and received tokens worth about $36,000. What all cases lacked was a rule over the resulting state, defined independently of the transaction builder and enforced during execution. Ethereum has no general mechanism for onchain code to inspect all the net state changes and events a transaction produces; EIP-7906 is one possible approach, alongside Clear Signing.
- [EIP-7906 PR: assertion inputs controlled by the transaction](https://github.com/ethereum/EIPs/pull/12391) was merged.

**Why it matters**
- For users, wallets could one day attach rules like "the Safe implementation must not change" or "receive at least this much", so a compromised frontend cannot produce a disastrous signature. For wallet and account developers, assertions will appear as a frame transaction mode, so it is worth designing now where the policies come from (who writes the rules).

### 2. Frame transactions: delegation frames and keyed nonces
**What happened**
- [EIP-8141 PR: add a set-delegation frame for codeless senders](https://github.com/ethereum/EIPs/pull/12421) and [EIP-8250 PR: let a transaction scope its nonce keys to the payer](https://github.com/ethereum/EIPs/pull/12422) (both by AnkushinDaniil).
- [Luca Donno: a closed native rollup devnet based on frames-devnet-0](https://x.com/donnoh_eth/status/2107130971095171114), 22:29. A native rollup inherits L1's state transition function directly, which greatly reduces complexity, governance and bug risk.

**Why it matters**
- A set-delegation frame lets an ordinary EOA set a delegation inside a frame transaction, which comes close to folding 7702's capability into native AA transactions. Scoping nonce keys to the payer matters for replay isolation in sponsored transactions. Together they shape how costly it is for wallets to move to frame transactions.
