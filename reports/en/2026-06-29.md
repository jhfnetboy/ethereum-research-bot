## Key topics

### 1. Privacy cryptography: indistinguishability obfuscation
**What happened**
- [Vitalik: a ten-thousand word monster post covering the entire tech tree behind the main lineage of obfuscation (iO) protocols](https://x.com/VitalikButerin/status/2071479076217348443), 13:21.
- [ethresear.ch: The Price of Forgery, measuring Sybil resistance in dollars (a paper)](https://ethresear.ch/t/the-price-of-forgery-measuring-sybil-resistance-in-dollars-a-paper/25316), 15:53 (porobov), proposing "how many dollars it costs to break a proof of personhood method" as a shared metric.

**Why it matters**
- For privacy: iO lets a program hide its internal logic and keys while running, and is seen as one of the ultimate tools of privacy cryptography; mapping its tech tree helps judge how far it is from practical use.

### 2. State and frame transactions
**What happened**
- [ethresear.ch: The Anatomy of Ethereum's State Access](https://ethresear.ch/t/the-anatomy-of-ethereum-s-state-access/25317), 17:37 (weiihann). Every transaction reads and writes balances, nonces, code and storage slots; as the chain grows, more state goes untouched for a long time, which is why proposals look at separating dormant state, expiring it or creating new forms of state. The report provides empirical data for that research.
- [EIP-7906: TXDIFF priced by EIP-2929 rules, duplicate paragraph removed](https://github.com/ethereum/EIPs/pull/11840) (forshtat), submitted and merged: storage slot parameters use `COLD_SLOAD_COST`/`WARM_STORAGE_READ_COST`, and balance and codehash parameters use `COLD_ACCOUNT_ACCESS_COST`/`WARM_STORAGE_READ_COST`, replacing a flat placeholder cost.
- ACDT #85 was held in the evening, with no notes to cite. RPC Standards #29 was held at 22:00, with no notes to cite.

**Why it matters**
- For accounts: state tiering and expiry proposals will eventually affect the cost of using dormant accounts, and state access data decides which approach hurts users least.
