## Key topics

### 1. A post-quantum account path
**What happened**
- [EIP-7819: add trailing data to the delegation designator](https://github.com/ethereum/EIPs/pull/12047) (shemnon), submitted, with a worked example storing ML-DSA public keys in the designator's trailing data and EIP-8141 code that accepts them.
- [New EIP: Precompiles for ML-DSA Verification](https://github.com/ethereum/EIPs/pull/12048) (shemnon), submitted as EIP-8355, a "just the FIPS" set of precompiles for all parameter sets. [Forum](https://ethereum-magicians.org/t/eip-8355-precompiles-for-ml-dsa-verification/29211), 07:55: three precompiles verify NIST security levels II, III and V (ML-DSA-44, 65 and 87); it overlaps with EIP-8051, the author lists four specific disagreements, and he would rather fold it into 8051 if those are resolved. [EIP-8081: propose EIP-8355 for inclusion](https://github.com/ethereum/EIPs/pull/12059), submitted.

**Why it matters**
- For wallets: an EOA delegating to contract code, a post-quantum public key in the delegation designator, and 8141 frame transactions verifying signatures with an ML-DSA precompile together let existing addresses migrate to post-quantum signatures without changing address; the precompile decides whether that verification cost is acceptable.

### 2. Gas and native rollups
**What happened**
- [New EIP: Net Gas Metering for Account Changes](https://github.com/ethereum/EIPs/pull/12058) (rakita), submitted as EIP-8358: a value-bearing call pays for each account whose balance changes for the first time in a transaction, later changes to that account cost less, and restoring the original balance earns a refund if the nonce is unchanged. With EIP-8038's `ACCOUNT_WRITE = 9000`, a call pays a 4000 base plus 2500 per clean account changed; the 2300 gas stipend becomes a floor on callee gas. An applied EIP-7702 authorization changes the authority's nonce, so later calls treat that account as changed.
- [EIP-8038: derive access list costs from cold access costs](https://github.com/ethereum/EIPs/pull/12056) (misilva73), submitted and merged: both access list costs were 3000, equal to the cold costs, and since a prepaid entry still pays `WARM_ACCESS` when touched, using an access list cost 3100 versus 3000 without one, inverting the EIP-2930 discount; both are now 2900.
- [New EIP: EVM Verification Key Registry](https://github.com/ethereum/EIPs/pull/12055) (donnoh), submitted as EIP-8357: a fixed-address system contract exposes fork-approved EVM verification key hashes and the stateless input `schema_id` (EIP-8025) each accepts, so native rollups can follow the current hash automatically or pin a registered one. [Forum](https://ethereum-magicians.org/t/eip-8357-evm-verification-key-registry/29222), 21:14.
- [EIP-8025: move to Draft](https://github.com/ethereum/EIPs/pull/11604) (frisitano), merged, filling in all sections.

**Why it matters**
- For wallet gas estimation: the access list fix directly affects the cost of transactions using 2930 access lists, and if 8358 is adopted, batches that pay the same account several times become cheaper.
