## Key topics

### 1. A custom signature path for 8141
**What happened**
- [New EIP: Frame authenticator signatures](https://github.com/ethereum/EIPs/pull/12244) (leekt), submitted, with a [Magicians thread](https://ethereum-magicians.org/t/eip-8397-frame-authenticator-signatures/29517) at 15:52; this is EIP-8397. A frame transaction can carry a custom authentication proof whose expensive cryptographic verification the protocol executes in a bounded, state-independent context; the signature object is `[scheme, signer, msg, signature]` with `scheme = AUTHENTICATOR (0x03)` and `signer` as the authenticator address. Each authentication is bounded by a fixed `AUTHENTICATOR_GAS_LIMIT`, with no per-transaction or per-key budget.

**Why it matters**
- The idea is close to 8130's authenticators but hands only the cryptographic check to the protocol: 8141 accounts can use post-quantum or passkey schemes without running the expensive verification in account code, in a state-independent, gas-fixed context, while the authorization policy is still decided by the account's own `VERIFY` frame.

### 2. Contracts, tooling and process
**What happened**
- [EF: heads-up for anyone maintaining L1 contracts](https://x.com/ethereumfndn/status/2092315755240906878), 01:18: Glamsterdam includes the EIP-8037 and EIP-8038 repricings; most contracts are unaffected, but a small set may break or degrade.
- [New EIP: contract storage layout descriptor format](https://github.com/ethereum/EIPs/pull/12247) (forshtat), submitted; originally ERCs#1841, reopened because interface standards should be EIPs. A language-neutral, extensible JSON format so explorers, debuggers, source verification, security tooling and wallets doing clear signing, transaction simulation and transaction assertions can map raw storage slots back to source-level variables.
- [EIP-5069: add EIP coordinator](https://github.com/ethereum/EIPs/pull/12241) was merged and then [rolled back](https://github.com/ethereum/EIPs/pull/12242), then resubmitted as [PR 12243](https://github.com/ethereum/EIPs/pull/12243).
- [EIP-8037: include non-zero balance in the description of an existent address](https://github.com/ethereum/EIPs/pull/12246) (awskii), submitted; [EIP-8148: update to match recent spec changes](https://github.com/ethereum/EIPs/pull/12245), submitted and merged.
- P2P networking #7 was held in the evening ([agenda](https://ethereum-magicians.org/t/p2p-networking-7-august-26-2026/29518), 19:08), with no notes to cite.

**Why it matters**
- For wallets: with a standard storage layout, a wallet can show the storage changes from a transaction simulation as readable variable changes, a building block for clear signing.
