## Key topics

### 1. ACDE #240: Hegotá non-headliner proposals
**What happened**
- ACDE #240 was held at 21:00. Per Ethereal news #30: Glamsterdam devnet-7 targets next week; disable and re-enable functionality is being added to the EIP-8282 builder execution requests contracts; repricing numbers are stable, pending benchmarking; the ePBS payload deadline is set to 6 seconds; the Glamsterdam mascot vote closes July 8.
- Hegotá non-headliners proposed (deadline for proposing is August 6): Thomas Thiery proposed EIP-8250 keyed nonces and EIP-8272 recent roots; Toni Wahrstätter proposed EIP-7862 delayed state root and EIP-8146 block access list sidecars; Ben Adams proposed the EIP-8298 SETCODEFROM code reuse instruction.
- [nixorokish: the deadline for proposing non-headlining features for Hegotá is August 6](https://x.com/nixorokish/status/2072694193772728812), 21:49.

**Why it matters**
- For privacy and accounts: 8250 and 8272 sit on top of frame transactions and let privacy dapp transactions resist censorship without relayers; SETCODEFROM concerns how accounts reuse code. All three directly shape account transactions.

### 2. EIP-8130, EIP-7928 and EIP-7997
**What happened**
- [EIP-8130: clarify actor policies and simplify the metadata field](https://github.com/ethereum/EIPs/pull/11847) (chunter-cb), submitted and merged, with no normative change: the one protocol guarantee is that a non-zero `policyType` confines the key's calls to its `manager`, and the 32-byte `commitment` is fully opaque, with meaning defined by the manager.
- [EIP-7928: revert 7702 tracking](https://github.com/ethereum/EIPs/pull/11838) (nerolation), merged, going back to "option 1": checks happen after warming, and the delegate read during resolution is all recorded. [EIP-7928: SSTORE access cost check](https://github.com/ethereum/EIPs/pull/11854), submitted, clarifying stipend and cold state tracking.
- EIP-7997 factory contract: [remove specification of nonce](https://github.com/ethereum/EIPs/pull/11846), merged; [clarify nonce for irregular state transition](https://github.com/ethereum/EIPs/pull/11850) (nerolation) and [add nonzero nonce to summary requirements](https://github.com/ethereum/EIPs/pull/11852) (frangio), submitted and merged; [replace Yul with mnemonics](https://github.com/ethereum/EIPs/pull/11849) and [clarify 7997](https://github.com/ethereum/EIPs/pull/11851), submitted.

**Why it matters**
- For accounts: EIP-8130 actor policies let an account grant a key limited rights; the protocol only guarantees the call scope and leaves the rest of the semantics to the manager contract, a basis for features like session keys. How EIP-7928 handles 7702 delegations decides how block access lists record EOA delegation, which affects parallel execution in clients.

### 3. Network level privacy and the transaction type debate
**What happened**
- [ethresear.ch: SPREAD, extending GossipSub with efficient anonymous dissemination](https://ethresear.ch/t/spread-extending-gossipsub-with-efficient-anonymous-dissemination/25343), 08:27 (Diogo Cardoso, Matheus Franco, Rodrigo Rodrigues), with a draft spec submitted to libp2p/specs and a reference implementation for go-libp2p-pubsub.
- [gakonst: on innovating by extending the EVM and adding new tx types, the upside at Tempo was very real: one click multi step actions, scoped account delegation, fee abstraction and secure custody](https://x.com/gakonst/status/2072666973717057718), 20:01.

**Why it matters**
- For privacy: a transaction propagating over the P2P network exposes the sender's IP, so network level anonymity is a precondition for onchain privacy. gakonst's view lines up with native account abstraction directions such as frame transactions and EIP-8130.
