## Key topics

### 1. Native AA: EIP-8141 heads for Hegotá
**What happened**
- [EIP-8081: add EIP-8141 to CFI and EIP-7716 and EIP-8205 to PFI](https://github.com/ethereum/EIPs/pull/11537) (dionysuzx), submitted, based on decisions at ACDE #233 and ACDC #177.
- [EIP-8141: add a value field to frames](https://github.com/ethereum/EIPs/pull/11534) (lightclient), submitted and merged: the author had preferred leaving execution of the user's operation to the account, but the focus is now on frames giving a good out of the box experience.
- [lightclient: nero_eth outlines how EIP-8141 frame transactions will reduce reliance on centralized services like relayers and improve privacy](https://x.com/lightclients/status/2044889767096254894), 04:24; [nero_eth: privacy protocol withdrawals can pay fees directly with no relayers, and privacy must have room in our mempools](https://x.com/nero_eth/status/2045010409560609147), 12:24.

**Why it matters**
- For accounts: CFI is the last gate before an upgrade, so once frame transactions are in Hegotá native AA becomes a mainnet roadmap item rather than a proposal; adding value to frames means simple transfers no longer have to route through account contract code.

### 2. Transactions and gas
**What happened**
- [EIP-8037: add a per-dimension block gas limit check](https://github.com/ethereum/EIPs/pull/11536) (misilva73), submitted: block gas limits are enforced separately for regular and state gas before execution, with updated `check_transaction` pseudocode.
- [EIP-7954: raise the contract code size limit to 64KiB](https://github.com/ethereum/EIPs/pull/11540) (Giulio2002), submitted, also raising the EIP-3860 initcode limit from 48KiB to 128KiB.
- [EIP-8037: refund state gas on all frame failures including top level](https://github.com/ethereum/EIPs/pull/11476) (qu0b), merged; [EIP-7928: change the block access index from uint16 to uint64](https://github.com/ethereum/EIPs/pull/11535) (nerolation), submitted.

**Why it matters**
- For users: with state gas as its own dimension, a block must stay under the limit in both dimensions, so whether a transaction fits depends on two kinds of resources; a looser code size limit directly changes how large contracts are deployed.
