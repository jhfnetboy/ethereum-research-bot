## Highlights
1. **EIP-8455**: RESERVOIR (0x4d) lets a contract see its full remaining budget and fixes sub-call measurements with two `gasleft()` reads that miss state gas paid by the reservoir.
2. **EIP-8450**: the withdrawal-address authorization path is gone, the BLS signing key is the only authority, and key changes are spaced at least 256 epochs apart.

## Key topics

### 1. Gas budgets and account AA
**What happened**
- [Magicians: EIP-8455 RESERVOIR opcode](https://ethereum-magicians.org/t/eip-8455-reservoir-opcode/30116), 16:17 (ja7ad), with 12 posts that day. EIP-8037 splits gas into execution gas and state gas, and state gas can be paid from a reservoir that `GAS` does not report; EIP-8141 frame transactions also have a per-frame `state_gas_left`. As a result, contracts cannot see their full remaining budget, and measuring a sub-call with two `gasleft()` readings under-counts state gas the reservoir paid for. RESERVOIR returns that amount, so together with `GAS` a contract can read its whole budget.
- [ethresear.ch: Ephemeral Rollup, the new "L1.5" of Ethereum](https://ethresear.ch/t/ephemeral-rollup-the-new-l1-5-of-ethereum/26187), 09:40 (namnc). Rollups made verification succinct but also hold their users' state, which is why every rollup needs an exit; native AA (EIP-8141 and related EIPs) and proof aggregation make keeping compute and state apart practical.
- [EFDevcon: leanSPHINCS, signing for the long run](https://x.com/EFDevcon/status/2115404460138823694), 18:25; EF researcher ncsgy will present at Devcon 8 on how hash-based signatures can secure smart accounts for a post-quantum future.

**Why it matters**
- If EIP-8455 is adopted, gas-measuring contracts such as relayer reimbursement or gas-metered meta-transactions can compute costs that include state gas accurately. L1.5 is another use of frame transactions: user state stays in L1 accounts and only compute is outsourced.

### 2. Signing security
**What happened**
- [Magicians: draft ERC STVA, secure transaction verification and authorization to stop blind signing and multisig UI attacks](https://ethereum-magicians.org/t/erc-draft-secure-transaction-verification-and-authorization-stva-stopping-blind-signing-multisig-ui-attacks/30106), 01:33, with 13 posts that day. Citing the February 2025 Bybit Safe multisig incident, the author argues that most high-value thefts no longer rely only on contract bugs but exploit blind signing of opaque data, and proposes a standard verification payload, an independent simulation interface and scoped capabilities so that "what you see is what you sign" becomes enforceable.
- [ERC-7943: fix the duplicate-id batch freeze bypass in uRWA1155](https://github.com/ethereum/ERCs/pull/2122) (xaler5). Repeating a `tokenId` in `safeBatchTransferFrom` let a holder move frozen tokens; transfers now check the running total per id.
- [lambdaclass: security fix disclosure for the PropAMM contract](https://x.com/class_lambda/status/2115183902876909722), 03:48; its factories on mainnet are not affected.

**Why it matters**
- For multisig and wallet teams, STVA points the same way as ERC-7730 clear signing and is worth following before Devcon. Projects using the uRWA1155 reference implementation need to upgrade.

## Other updates
- [EIP-8450: BLS-authorized key changes, builders, crypto interface](https://github.com/ethereum/EIPs/pull/12592) (kevaundray). It removes the withdrawal-address path (the EIP-7685 request type, the execution-layer request contract and the pending-authorization queue), changes `requires` from 7002, 7685, 7916 to 7495, 7732, 7916 so the EIP no longer changes the execution layer, and makes the BLS signing key the only authority that registers and replaces keys, with changes limited by `MIN_PQ_KEY_CHANGE_DELAY = 256` epochs.
