## Key topics

### 1. Spec details for native AA and 7702
**What happened**
- [EIP-8141: allow arbitrary signature data to avoid a circular dependency for custom verifiers](https://github.com/ethereum/EIPs/pull/11837) (lightclient), submitted. The author originally meant to include this in an earlier PR but decided it was unneeded; it turns out to be required if custom verifiers are to use the canonical signing hash.
- [EIP-7928: revert 7702 tracking](https://github.com/ethereum/EIPs/pull/11838) (nerolation), submitted; based on Discord discussions it goes back to "option 1": checks after warming, the delegate read during resolution, and everything stays in the BAL.
- [EIP-8081: PFI EIP-8279](https://github.com/ethereum/EIPs/pull/11839) (nerolation), submitted and merged; [EIP-8141: restore Behavior section](https://github.com/ethereum/EIPs/pull/11810), merged.

**Why it matters**
- For wallets: if the signing hash itself depends on signature data, custom verifiers (such as post-quantum or multisig verifiers) cannot sign over the canonical hash. For BALs: calling a 7702 account reads its delegation target, and if the BAL does not record that read, parallel execution and prefetching would miss it.

### 2. Security of EIP-7702 delegation contracts
**What happened**
- [ChainSecurity: audited CoW Swap's Solver7702Delegate](https://x.com/chain_security/status/2070466832327147766), 18:18, an EIP-7702 delegation target for CoW Protocol solvers.

**Why it matters**
- For 7702 users: delegating an EOA to a contract means handing the account to that contract's code, so audits of delegation targets and their public results are the base of security in the 7702 ecosystem.
