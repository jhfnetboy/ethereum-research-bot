## Key topics

### 1. Privacy: from broadcasters to the protocol
**What happened**
- [soispoke: Alice swaps privately on L1](https://x.com/soispoke/status/2034587465382514773), 18:07: privacy protocol users today rely on broadcasters that can see, frontrun and censor their transactions; the thread shows how four future protocol upgrades remove that dependency step by step, starting with native AA (EIP-8141) and 2D nonces.
- [EIP-8182: add a delivery key registry, X-Wing baseline scheme, remove delegated registration](https://github.com/ethereum/EIPs/pull/11423) (RogerPodacter), submitted and merged, updating the enshrined private transfers EIP merged on March 17.
- [ethresear.ch: Post-Quantum Threats to Ethereum Privacy](https://ethresear.ch/t/post-quantum-threats-to-ethereum-privacy/24450), 16:29: under harvest now decrypt later, migrating long lived confidential data is more urgent than migrating authentication, since signature forgery can be partly remedied by hard forks and key migration while harvested ciphertexts cannot be recovered.

**Why it matters**
- For privacy: X-Wing is a hybrid classical and post-quantum key encapsulation, so using it for delivery keys answers the harvest now decrypt later threat; native AA lets users pay their own gas instead of handing transactions to a relayer.

### 2. Accounts: Sandboxed Smart Wallet
**What happened**
- [Add ERC: Sandboxed Smart Wallet](https://github.com/ethereum/ERCs/pull/1609) (PowerStream3604), submitted: interfaces and behavior for a sandboxed smart wallet for secure agentic automation; [Magicians thread ERC-8199](https://ethereum-magicians.org/t/erc-8199-sandboxed-smart-wallet/28029), 22:31.

**Why it matters**
- For accounts: AI agents acting for users need bounded permissions, and defining a sandbox at the contract account layer is a natural extension of ERC-4337 and EIP-7702 accounts.
