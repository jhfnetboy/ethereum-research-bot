## Key topics

### 1. Transactions and signatures: Falcon-512 in EIP-8175
**What happened**
- [EIP-8175: add the Falcon-512 post-quantum signature scheme](https://github.com/ethereum/EIPs/pull/11431) (Giulio2002), submitted: adds Falcon-512 (NIST FIPS 206) as a third signature type for composable transactions, SIG_FALCON512 (0x03), with parameter table and signature format entries.
- [tcoratger: recommending Blockstream Research material on hash based signature schemes for Bitcoin](https://x.com/tcoratger/status/2035145555546948027), 07:04.

**Why it matters**
- For transactions: listing post-quantum signature IDs directly in a transaction type is an alternative post-quantum path to EIP-8141 frame transactions, giving a comparison point for the Hegotá choice.

### 2. EVM: EVMification
**What happened**
- [Add EIP: EVMification](https://github.com/ethereum/EIPs/pull/11432) (kevaundray), submitted; [Magicians thread EIP-8200](https://ethereum-magicians.org/t/eip-8200-evmification/28036), 07:51: replace precompiles such as blake2f, ripemd160 and the BLS12 map to curve precompiles with equivalent bytecode.

**Why it matters**
- For gas: rarely used precompiles turned into ordinary contracts are priced by actual EVM execution, so clients and zkVMs maintain less special code, though callers' gas costs change.
