## Highlights
1. **AA transaction type stands alone**: the transaction type can ship first and the Keystore can follow.
2. **Block production safety**: EIP-8141 bounds producer re-execution of unapproving validation prefixes.
3. **Alternative mempools**: ERC-8421 is reputation-based, similar in structure to ERC-7562 and mostly backward compatible, and more permissive than the in-protocol canonical mempool.
4. **ePBS**: after Glamsterdam, stakers no longer need sidecars like mev-boost or commit-boost to receive third-party blocks.

## Key topics

### 1. Splitting native AA, and mempools
**What happened**
- [New EIP: AA transaction type](https://github.com/ethereum/EIPs/pull/12385) (chunter-cb). An EIP-2718 transaction type split out of EIP-8130 with no Keystore dependency, usable by today's EOAs with native secp256k1 authentication: phased call batching (with native value in calls), gas sponsorship with bound and open payer modes, 2D nonces (key 0 is the account nonce) and a nonce-free mode, and in-band EIP-7702-style code delegation.
- [EIP-8130: scope to the Keystore and move the transaction type to a new EIP](https://github.com/ethereum/EIPs/pull/12386), covering actors, authenticators, scopes, policies, lock, account creation and import, and signature verification.
- [Magicians: ERC-8421 frame transaction alternative mempools](https://ethereum-magicians.org/t/erc-8421-frame-transaction-alternative-mempools/29800), 18:51 (forshtat), similar in structure to and mostly backward compatible with ERC-7562's validation rules for ERC-4337, a reputation-based system more permissive than the canonical mempool; conceptually close to MATCHA, with the main difference being the unit of accounting (gas used versus transactions seen).
- [EIP-8141: bound producer-side re-execution of an unapproving validation prefix](https://github.com/ethereum/EIPs/pull/12213) (AnkushinDaniil) was merged. The mempool section already bounds admission and head-change revalidation, but not block production: a frame transaction pays nothing until one of its frames approves. [EIP-8141: replace 7623 with 7976](https://github.com/ethereum/EIPs/pull/12395) (lightclient) was merged; [deploy the frames expiry verifier as a standard contract](https://github.com/ethereum/EIPs/pull/12387).
- [EIP-7906: assertion inputs controlled by the transaction](https://github.com/ethereum/EIPs/pull/12391): an assertion that takes reference values (a price, a threshold, a permitted spender) from state the body could write is still steerable.

**Why it matters**
- For wallets, EIP-8430 gives existing EOAs batching, sponsorship and 2D nonces without changing address, and L2s like Base may ship it early; L1 goes with EIP-8141. The two differ in transaction fields and mempool rules, so SDKs need to support each. Alternative mempools leave a path for validation-heavy transactions such as those from privacy apps.

### 2. Glamsterdam and FOCIL
**What happened**
- [ralexstokes: Glamsterdam brings blocks built without trusted relays, with Sepolia upgrading October 6](https://x.com/ralexstokes/status/2104719613519184019), 06:47; Hoodi and mainnet dates will be announced separately.
- [ladislaus0x: with ePBS, staking operators no longer need mev-boost or commit-boost to receive third-party blocks](https://x.com/ladislaus0x/status/2104868279521091610), 16:37; the beacon node collects and selects bids itself, and builder preferences are set natively in the validator client.
- [EIP-7805: Profile 2 omission claims and per-list VERIFY budgets](https://github.com/ethereum/EIPs/pull/12394), with joint FOCIL and frame activation; [EIP-8369: deterministic Profile 2 budgets and replay](https://github.com/ethereum/EIPs/pull/12396).

**Why it matters**
- Stakers should check relay and sidecar configurations before the upgrade. For FOCIL to force inclusion of frame transactions, each inclusion list's validation work needs a budget.
