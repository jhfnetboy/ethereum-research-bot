## Key topics

### 1. Privacy and accounts: EIP-8182 and SETCODEFROM
**What happened**
- [EIP-8182: move to Review](https://github.com/ethereum/EIPs/pull/11825) (RogerPodacter), merged. EIP-8182 defines protocol level private ETH and ERC-20 transfers.
- [New EIP: SETCODEFROM code reuse instruction](https://github.com/ethereum/EIPs/pull/11800) (colinlyguo), merged as EIP-8298. The PR says the direction comes from Ben Adams' idea on ACDE of combining the goals of EIP-7851 and EIP-8058; it stays in Draft for now.
- [EIP-8219: add revert and opcode details](https://github.com/ethereum/EIPs/pull/11842) (ritzdorf), merged.
- [EIP-2542: move to Withdrawn](https://github.com/ethereum/EIPs/pull/11773) (forshtat), merged.

**Why it matters**
- For privacy: EIP-8182 reaching Review means a spec for protocol level private transfers is now in a stage where it can be formally reviewed, so users would no longer have to depend only on application level privacy pools.
- For accounts: SETCODEFROM lets an account reuse the code of an already deployed contract; it merges the EIP-7851 and EIP-8058 directions, and Ben Adams proposed it for Hegotá on ACDE on July 2.

### 2. Account transactions and gas
**What happened**
- [EIP-2780: move state-dependent charges to runtime (cold surcharge, new-account state gas)](https://github.com/ethereum/EIPs/pull/11844) (rakita), submitted. Intrinsic gas keeps only the bare minimum needed to include a transaction in a block: account access is split into an intrinsic `WARM_ACCESS` floor plus a runtime cold surcharge, and the create transaction's new-account state gas is charged conditionally at runtime.
- [New EIP: Increase Calldata Floor Cost to 96](https://github.com/ethereum/EIPs/pull/11821) (misilva73), merged as EIP-8311, raising the calldata floor from 64/64 to 96/96 gas per byte; [EIP-8311: clarify the scope of the TOTAL_COST_FLOOR_PER_TOKEN change](https://github.com/ethereum/EIPs/pull/11843), submitted and merged.
- [EIP-7997: remove specification of nonce](https://github.com/ethereum/EIPs/pull/11846) (fjl), submitted, since the factory's nonce increases on every use and requiring it to be 1 makes no sense.

**Why it matters**
- For wallets: under EIP-2780 whether a transaction can be included depends only on a state-independent minimum, which simplifies gas estimation in wallets and transaction validation in nodes, while state-dependent costs are charged at execution by actual access. EIP-8311 makes calldata heavy transactions more expensive, which affects data heavy account operations.

### 3. Post-quantum and state
**What happened**
- [New EIP: Post-Quantum Keystore for Stateful Keys](https://github.com/ethereum/EIPs/pull/11820) (ch4r10t33r), merged as EIP-8310. It extends EIP-2335 so the encrypted secret can be an XMSS seed as used by the lean consensus layer, and adds the machinery a consumable key needs.
- [New EIP: State Tiering by Periods](https://github.com/ethereum/EIPs/pull/11788) and [New EIP: Fixed-Cutoff State Tiering](https://github.com/ethereum/EIPs/pull/11790) (weiihann), merged as EIP-8295 and EIP-8296.
- [ethresear.ch: Is the slot-0 reorg cost fixable? ePBS attestation deadline study](https://ethresear.ch/t/is-the-slot-0-reorg-cost-fixable-epbs-attestation-deadline-study/25338), 14:57 (CPerezz). Twenty-one months of mainnet data point to fixable production engineering, with one exchange alone causing about 18% of the epoch boundary problems.
