## Key topics

### 1. Mempool and gas semantics for native AA
**What happened**
- [EIP-8130: add a four-tier authenticator classification](https://github.com/ethereum/EIPs/pull/12210) (chunter-cb), submitted. It replaces the binary canonical/permissive description with four tiers, CANONICAL, PURE, BOUNDED and ARBITRARY, that classify a declared authenticator by code hash; consensus validity is unchanged, and under the L1 profile any authenticator returning within `MAX_AUTHENTICATION_GAS` remains valid in a block, while the tiers govern mempool propagation and revalidation.
- [EIP-8130: adoption profiles, bounded auth gas and timestamp normalization](https://github.com/ethereum/EIPs/pull/12204), merged.
- [EIP-8141: charge the resolved target's access at frame entry](https://github.com/ethereum/EIPs/pull/12211) (gurukamath), submitted. The spec charges a `resolved_target`'s warm/cold access within the frame's own `limits.execution` but never says when, and defines no execution cost for frames dispatched to the default code, so implementations can diverge on `gas_used.execution`, on warmth and even on validity. The same author's [scope APPROVE failure modes to the current call frame](https://github.com/ethereum/EIPs/pull/12212) was submitted the same day.
- [EIP-8141: bound producer-side re-execution of an unapproving validation prefix](https://github.com/ethereum/EIPs/pull/12213) (AnkushinDaniil), submitted. The mempool section already bounds admission and head-change revalidation but not re-execution by the block producer.
- [EIP-8141: fix the calldata floor to use the EIP-7976 uniform token count](https://github.com/ethereum/EIPs/pull/12209) (ilitteri), submitted. The formula multiplied a weighted count by 16, which prices zero bytes at 16 gas and nonzero bytes at 64, matching neither EIP-7623 (10/40) nor EIP-7976 (64/64).

**Why it matters**
- For bundlers and wallets: the authenticator tier decides whether an account's transactions are broadcast by the public mempool. An account using a custom authenticator (for example a new post-quantum signature) is valid in consensus but may not be relayed by every node.

### 2. ACDC #185 and the Glamsterdam testnets
**What happened**
- [terencechain: Platåberget upgrades to Glamsterdam in about six hours, the first public testnet to do so](https://x.com/terencechain/status/2090242248038637736), 07:59.
- ACDC #185 (as summarized by Ethereal news #36): Platåberget activated Glamsterdam, but a builder deposit caching issue at the upgrade transition caused non-finality; a non-finality devnet targets the week after next with about 1,000 nodes; the proposal for public testnets is Sepolia on September 28 and Hoodi on October 26; EIP-7610 was declined, superseded by EIP-8253, which is already PFI; Hegotá non-headliner presentations covered EIP-8333, EIP-8379 and EIP-8383, with client preferences due mid-September.
- [EIP-7773: remove EIP-7610 from Glamsterdam](https://github.com/ethereum/EIPs/pull/12189), merged.

**Why it matters**
- For application developers: with the public testnet dates proposed, there is a timeline for testing gas repricing and ePBS on Sepolia.
