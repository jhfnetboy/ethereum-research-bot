## Key topics

### 1. Patching the native AA specs
**What happened**
- [EIP-8141: ban SLOTNUM during validation-prefix execution](https://github.com/ethereum/EIPs/pull/12066) (AnkushinDaniil), merged. The validation prefix already bans opcodes whose value changes between admission and inclusion: `TIMESTAMP`, `NUMBER`, `PREVRANDAO`, `BASEFEE`, `BLOBBASEFEE`; a prefix branching on them can pass simulation at admission and revert on inclusion. `SLOTNUM` has exactly that property but was missing because the list predates it.
- [EIP-8130: align with Keystore contract](https://github.com/ethereum/EIPs/pull/12135), merged, followed by [audit reconciliation (self-actor revoke, authenticator allowlist)](https://github.com/ethereum/EIPs/pull/12148) (chunter-cb), submitted and merged the same day. It changes only the spec, not the contract, and simplifies `RevokeActor` to uniformly delete the actor config and its policy.
- [EIP-8141: link the first reference to each cited proposal](https://github.com/ethereum/EIPs/pull/12121), merged.

**Why it matters**
- For bundlers and mempools: a validation result must still hold at inclusion, otherwise nodes propagate transactions doomed to fail, which is a DoS risk. The 8130 audit reconciliation shows Base's implementation has been audited.

### 2. The gas limit and address poisoning
**What happened**
- [trent_vanepps: part of me thinks we should not scale the gas limit further until demand catches up enough to make address poisoning uneconomical](https://x.com/trent_vanepps/status/2087243471132266865), 01:23, before concluding it is probably an impossible problem.

**Why it matters**
- Cheaper blockspace also makes spam cheaper, and address poisoning has to be countered by how wallets display and warn.
