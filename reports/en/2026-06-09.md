## Key topics

### 1. Account EIPs among the Hegotá candidates
**What happened**
- [EIP-8081: add newly PFI'd EIPs](https://github.com/ethereum/EIPs/pull/11786) (nixorokish), submitted and merged: EIP-7851 code controlled EOA delegation and EIP-8151 ECDSA authority deactivation aware ecRecover (both proposed by lightclient at ACDE #238), EIP-8131 adding auth data to the EIP-7623 floor (nerolation, ACDE #238), EIP-7979 call and return opcodes (gcolvin, ACDE #235) and others.
- [EIP-8130: rename verifier to authenticator](https://github.com/ethereum/EIPs/pull/11785) (chunter-cb), submitted and merged; [EIP-8130: clarifications and clean up](https://github.com/ethereum/EIPs/pull/11782), submitted and merged.

**Why it matters**
- For EOA users: EIP-7702 lets an EOA delegate to code, but the original key keeps full control. With 7851 and 8151 now PFI, the migration path of deactivating the original ECDSA key so the account is controlled only by code is formally in scope for Hegotá.

### 2. Privacy: 4337 relaying and STRK20

[Eli Ben-Sasson: privacy is coming to Starknet today](https://x.com/EliBenSasson/status/2064195119201312816), 10:57; [Eli: whether upgrading to a quantum-safe wallet or switching to shielded mode, users should not have to worry](https://x.com/EliBenSasson/status/2064333293068116023), 20:06.
- [aztecnetwork: work with Wonderland on new token standards, developer tooling and wallet UX](https://x.com/aztecnetwork/status/2064046503304540622), 01:06.

**Why it matters**
- For privacy users: when withdrawing from a privacy pool to a fresh address, that address has no ETH for gas, so users usually depend on relayers. Relaying withdrawals through a 4337 paymaster or bundler reuses general AA infrastructure to solve this.
