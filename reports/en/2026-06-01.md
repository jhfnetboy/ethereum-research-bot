## Key topics

### 1. Native AA: EIP-8250 and EIP-8130
**What happened**
- [EIP-8250: add support for nonce key sets](https://github.com/ethereum/EIPs/pull/11749) (soispoke), submitted and merged: moves from a single keyed nonce `(nonce_key, nonce_seq)` to a bounded key set `(nonce_keys, nonce_seq)`.
- [EIP-8130: add delegated account creation](https://github.com/ethereum/EIPs/pull/11751) (chunter-cb), submitted as a discussion draft: the create entry can produce an EIP-7702 delegated account in addition to placed bytecode, without a new entry type.
- [EIP-8130: define a signature invariant, nonce free replay identifier](https://github.com/ethereum/EIPs/pull/11752) (chunter-cb), submitted: the spec only said "deduplicate by transaction hash", but the standard transaction hash commits to `sender_auth` and `payer_auth`, which does not achieve one logical transaction per window.
- [nero_eth: does Ethereum need an enshrined deterministic factory (EIP-7997)?](https://x.com/nero_eth/status/2061478161578127473), 23:01; factories such as Arachnid, ERC-2470 and CreateX sit at the same address across chains today thanks to Nick's method of a presigned transaction.

**Why it matters**
- For accounts: declaring several nonce keys in one transaction lets parallel transactions express richer ordering and exclusion; if nonce free transactions were deduplicated by transaction hash, a new signature would replay the same logical transaction, so the identifier has to be signature invariant. A deterministic factory decides whether a smart account can get the same address on every chain.
