## Key topics

### 1. Account and transaction rules: SETCODEFROM on the 4337 ban list
**What happened**
- [ERC-7562 PR: block SETCODEFROM](https://github.com/ethereum/ERCs/pull/2066) (CPerezz, merged the next day). ERC-7562 sets the opcode and storage access limits that 4337 bundlers apply to UserOperation validation.
- [EIP-8141 PR: state the EIP-1559 fee validity rules and define effective_gas_price](https://github.com/ethereum/EIPs/pull/12486) (AnkushinDaniil).
- [EIP-8298 closes spec gaps and assigns opcode 0xA7](https://github.com/ethereum/EIPs/pull/12480), merged.

**Why it matters**
- If validation can change code, one UserOperation can invalidate others in the same batch and attack the public mempool, and banning SETCODEFROM closes that path. For 4337 account developers: do not rely on code changes inside `validateUserOp`. The frame transaction fee rules decide how wallets and RPCs estimate and display fees.

### 2. Privacy by default, starting with stealth addresses
**What happened**
- [Kassandra: the goal is for privacy to be the norm for Ethereum users](https://x.com/kassandraETH/status/2109625616156828000), 19:41. Step one is wallets interoperating on basic stealth address support, but first comes a post-quantum private stealth address scheme.
- [Magicians: a private stablecoin on Ethereum backed by USDC/USDT](https://ethereum-magicians.org/t/private-stablecoin-on-ethereum-backed-by-usdc-usdt/29946), 07:24, the same project as the ethresear.ch post three days earlier, with 11 posts that day.
- [StarkWare: Europol's report on quantum threats mentions account abstraction and ZK-STARKs](https://x.com/StarkWareLtd/status/2109509154314518979), 11:59, as tools to reduce wallets' quantum exposure.

**Why it matters**
- Instead of users seeking out privacy apps, wallets would support private receiving by default, which needs one standard that every wallet implements. Solving post-quantum first keeps today's private payment records from being unmasked later.
