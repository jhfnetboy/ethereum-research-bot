## Key topics

### 1. Spec progress on both native AA paths
**What happened**
- [EIP-8141: spec cleanup and clarifications](https://github.com/ethereum/EIPs/pull/11814) (morph-dev), merged. `sig.signer` can be empty and defaults to `tx.sender`; raw `sig.signature` bytes are elided from every `sig_hash`, because a transaction is valid only if all signatures are valid, so committing to `sig.msg` already commits to the signatures indirectly, and keeping the bytes would rule out future signature aggregation; in the mempool, the expiry verifier frame can only be the first frame in the list.
- [EIP-8130: renumber AA transaction types and add an eth_call/eth_estimateGas RPC extension](https://github.com/ethereum/EIPs/pull/11903) (chunter-cb), submitted. `AA_TX_TYPE` goes from `0x7B` to `0x79` and `AA_PAYER_TYPE` from `0x7C` to `0x7A`; the RPC accepts the AA transaction fields (`sender`, `nonceKey`, `accountChanges`, `calls`, `expiry`, `payer` and more) and prices the request as an AA transaction, since authentication gas depends on the auth blob's shape rather than a valid signature.

**Why it matters**
- For wallets and bundlers: 8130's estimation extension lets wallets estimate gas before signing, and 8141 keeping signature bytes out of the signing hash is a precondition for aggregating signatures across transactions in future, post-quantum ones included.
