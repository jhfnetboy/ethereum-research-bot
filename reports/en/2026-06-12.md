## Key topics

### 1. SETCODEFROM: a lower level code adoption primitive
**What happened**
- [New EIP: SETCODEFROM Code Reuse Instruction](https://github.com/ethereum/EIPs/pull/11800) (colinlyguo), submitted, with a [Magicians thread](https://ethereum-magicians.org/t/eip-8298-setcodefrom-code-reuse-instruction/28779) at 22:10; this is EIP-8298. It comes from benaadams' idea on an ACDE call to combine the goals of EIP-7851 and EIP-8058: a new EVM instruction lets the current account adopt the code hash of an existing deployed contract. The source is a live account address rather than a raw code hash, so the adopted code is tied to the current consensus state. There are two main uses. First, deployment cost (the problem EIP-8058 targets): contracts with identical runtime code initialize their own storage and then adopt shared code without paying code deposit gas again for bytecode clients already store, which matters more once EIP-8037 makes deployment more expensive. Second, EOA migration with ECDSA authority disabled (the problem EIP-7851 targets): migration code initializes wallet state, including post-quantum wallet state, then adopts regular wallet code; once the account has regular code, ECDSA transaction origination is disabled under EIP-3607 and EIP-7702 redelegation through the old ECDSA key is no longer available.

**Why it matters**
- For accounts: this gives a path to fully migrate an EOA to a smart account (including a post-quantum account), after which the old key stops working, closing the gap where the original key still controls an account after an EIP-7702 delegation.

### 2. Verifying post-quantum signatures on the EVM
**What happened**
- [ethresear.ch: SPHINCS minus, efficient stateless post-quantum signature verification on the EVM](https://ethresear.ch/t/sphincs-minus-efficient-stateless-post-quantum-signature-verification-on-the-evm/25165), 20:15 (nicocsgy), with thanks to Vitalik, Justin Drake, the EF PQ and cryptography team and others. Starting from the fact that quantum computers will eventually break ECDSA, it discusses how stateless hash-based signatures can be verified on the EVM at acceptable cost.
- [Magicians: EIP-8292 PQ Attestation Aggregators](https://ethereum-magicians.org/t/eip-8292-pq-attestation-aggregators/28778), 18:11.

**Why it matters**
- For accounts: smart accounts can switch to post-quantum signatures at the contract layer first, and verification cost decides whether that path is practical. A stateless scheme does not require wallets to track one-time key usage, which suits ordinary users better.

### 3. Gas and the mempool
**What happened**
- [EIP-7904: convert to Informational (no compute repricing needed)](https://github.com/ethereum/EIPs/pull/11622) (misilva73), merged. The gas analysis was rerun with the EIP-7928 (BAL) optimizations stabilized; at the 100 Mgas/s target, every examined compute operation and precompile clears the target at its current gas cost. The EIP is retitled "Compute Gas Cost Analysis".
- [EIP-8038: add preliminary numbers](https://github.com/ethereum/EIPs/pull/11802) (misilva73), submitted.
- [ErigonEth: joining the new Encrypt the Mempool Coalition](https://x.com/ErigonEth/status/2065328301795668015), 14:00, pushing to include an EIP that encrypts the Ethereum mempool in the I* hard fork to stop toxic MEV and real-time censorship.

**Why it matters**
- For users: compute operations do not get more expensive, so Glamsterdam's repricing is focused on state access. An encrypted mempool keeps transaction contents hidden until inclusion, which reduces sandwich attacks.
