## Key topics

### 1. Transaction format: EIP-8175 capabilities
**What happened**
- [EIP-8175: CALL/CREATE capabilities, fee_auth and new opcodes](https://github.com/ethereum/EIPs/pull/11490) (rakita), submitted and merged: moves to, value and data into typed CALL and CREATE capabilities so the envelope becomes a pure fee and auth container, adds programmable fee delegation through a fee_auth field, and adds three opcodes, RETURNETH, SIG (signature introspection) and SIGHASH.

**Why it matters**
- For gas: fee_auth lets third parties pay gas under programmable rules, the same goal as EIP-8141's paymaster frames but placed in the envelope rather than an execution frame, which keeps mempool validation simpler.

### 2. Native AA: EIP-8141 fixes
**What happened**
- [EIP-8141: fix APPROVE scopes, default code and add a VERIFY frame count check](https://github.com/ethereum/EIPs/pull/11488) (chiranjeev13), submitted: since sender_approved and payer_approved are one shot flags, adds a static check of at most 2 VERIFY frames; fixes stale APPROVE scope values in the structural rules; removes the frame.target != tx.sender check from default VERIFY code so any EOA can act as paymaster.

**Why it matters**
- For accounts: letting any EOA be a paymaster means a friend or service can pay someone's gas from a plain account without deploying a contract.
