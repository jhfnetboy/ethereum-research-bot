## Key topics

### 1. Wallet infrastructure for frame transactions
**What happened**
- [New EIP: Frame Paymaster Web Service](https://github.com/ethereum/EIPs/pull/12175) (leekt), submitted. It defines a wallet-to-paymaster web service flow for EIP-8141 frame transactions: `pm_getFramePaymasterStubData` returns gas-safe, paymaster-controlled frame and signature stubs, the wallet assembles the complete unsigned FrameTx and estimates it with the EIP-8141 estimation RPC.
- [EIP-8141: define a FrameTx gas estimation RPC](https://github.com/ethereum/EIPs/pull/12176) (leekt), submitted. It defines `eth_estimateFrameTransactionGas` directly in EIP-8141 because each frame needs independent execution and state gas limits; `null` limits are estimation targets and non-null limits are caller-supplied caps, the call returns intrinsic gas plus per-frame limits, and it requires a confirmation execution with exactly the returned limits.
- [Derek Chiang: I wrote Ethlabs' AA opinions, and as a coauthor I still rated Frames A rather than S](https://x.com/decentrek/status/2089040907282903129), 00:25, because S-tier requires an EIP to be substantially final.

**Why it matters**
- For wallets and paymaster operators: the `pm_` interfaces and gas estimation of the ERC-4337 era do not carry over to frame transactions, so native AA needs new service standards before launch, or every wallet ends up writing its own.

### 2. Platåberget and Glamsterdam testing
**What happened**
- [EF blog: announcing the Platåberget testnet](https://blog.ethereum.org/en/2026/08/17/plataberget-testnet); [ethPandaOps: Platåberget is our Glamsterdam-focused testnet](https://x.com/ethPandaOps/status/2089333243946377624), 19:47. Per the blog, unlike short-lived devnets it is meant to run for a few months; the validator set is small but publicly joinable, with genesis bootstrapped from public deposits; the Glamsterdam fork on the testnet is scheduled for August 20; and the gas repricings touch every wallet, indexer and gas estimator, so tools that rely on a hardcapped maximum gas limit will break.

**Why it matters**
- For application developers: this is the public place to validate ePBS flows and gas changes before mainnet.
