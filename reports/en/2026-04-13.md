## Key topics

### 1. Native AA: tightening EIP-8141
**What happened**
- [EIP-8141: tighten spec](https://github.com/ethereum/EIPs/pull/11521) (benaadams), submitted: splits the packed frame `mode` field into `mode` and `flags`, adds `FRAMEPARAM` and an explicit `resolved_target`, making the frame model, approval semantics, default code behavior and public mempool rules more explicit and internally consistent.

**Why it matters**
- For accounts: for frame transactions to underpin native AA, clients and wallets need an identical understanding of which frame approved what, how default code runs and what the mempool accepts; spec precision decides whether multiple clients can implement it.

### 2. Transactions and gas: EIP-8037 state gas accounting
**What happened**
- [EIP-8037: clarify that spillover state gas still increments execution_state_gas_used](https://github.com/ethereum/EIPs/pull/11522) (qu0b), submitted: when a state gas charge exceeds `state_gas_reservoir` and spills into `gas_left`, it still counts fully as state gas; counters are classified by cost type, not funding source.
- [EIP-8037: more clarifications for state gas accounting](https://github.com/ethereum/EIPs/pull/11523) (spencer-tb), submitted, consolidating points from misilva73's state gas accounting review.

**Why it matters**
- For users: EIP-8037 prices state creation separately, and any mismatch in accounting rules between clients would split consensus; these clarifications remove ambiguity during the devnet phase.

### 3. Security and privacy
**What happened**
- [growthepie: another mass address poisoning attack appears to be underway on mainnet; native ETH transfers hit 2.8 million the day before, 100% above baseline, so double check recipient addresses](https://x.com/growthepie_eth/status/2043672907952410668), 19:49.
- [Magicians: ERC-8227 Encrypted Token](https://ethereum-magicians.org/t/erc-8227-encrypted-token/28214), 11:50 (Valisthea), where balances return as FHE ciphertexts and transfers are verified with ZK proofs; the same author also proposed [ERC-8229 FHE Computation Verification](https://ethereum-magicians.org/t/erc-8229-fhe-computation-verification/28217), 17:03.
- [Nethermind: wallets rebuild transaction history by scanning chain events, which slows as the chain grows; comparing eth_getLogs with and without Log Index](https://x.com/Nethermind/status/2043625747739222503), 16:42.

**Why it matters**
- For users: address poisoning exploits the habit of checking only the first and last characters, so wallet address books and lookalike address warnings are the most direct defense.
