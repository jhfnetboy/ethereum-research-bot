## Key topics

### 1. Native AA: FOCIL and frame transactions
**What happened**
- [soispoke: given the Hegotá discussion on which EL headliner ships with FOCIL, a post on how FOCIL and frame transactions interact](https://x.com/soispoke/status/2033500624742916136), 18:08; [the Magicians post](https://ethereum-magicians.org/t/focil-native-account-abstraction/27999): FOCIL checks omitted inclusion list transactions with a nonce and balance check against post state, which works for EOAs, but native AA transactions need VERIFY frames executed to judge validity, so it defines a public mempool eligible FrameTx subset with bounded VERIFY execution against post state and a per list VERIFY gas budget to cap attester work.

**Why it matters**
- For accounts: if smart account transactions cannot be protected by inclusion lists, native AA users miss FOCIL's censorship resistance; this design lets the two ship together in Hegotá.

### 2. Transactions and signatures
**What happened**
- [Add EIP: Cryptographically Agile Transactions](https://github.com/ethereum/EIPs/pull/11413) (shemnon), submitted; [Magicians: EIP-8197 CATX](https://ethereum-magicians.org/t/eip-8197-cryptographically-agile-transactions-catx/28003), 23:11: an EIP-2718 format separating the body from signatures, with each signature committing to its position, supporting multisig and future ZK signature aggregation, and usable for EIP-8141 frame transactions.
- [EIP-8037: align with EIP-7928 gas validation phases](https://github.com/ethereum/EIPs/pull/11414) (nerolation), submitted: classifies cost parameters by pre and post state validation phases and fixes the CREATE path formula.
- [Add EIP: snap/2 BAL based state healing](https://github.com/ethereum/EIPs/pull/11391) (nerolation), merged.

**Why it matters**
- For users: decoupling signatures from transaction semantics means post-quantum migration only adds signature types instead of redefining every transaction format.
