## Key topics

### 1. Native AA: transaction expiry
**What happened**
- [EIP-8141: add an EXPIRY_VERIFIER frame for tx expiry](https://github.com/ethereum/EIPs/pull/11662) (nerolation), merged: expiry is set through a `VERIFY` frame targeting `EXPIRY_VERIFIER`, and `VERIFY` is relaxed to invalidate the transaction on revert.
- [EIP-7851: tweak wording based on forum discussions](https://github.com/ethereum/EIPs/pull/11672) (colinlyguo), submitted and merged, clarifying frame-local execution semantics and transaction validity.

**Why it matters**
- For users: a transaction with an expiry cannot linger in the mempool and be included at a bad moment, a basic protection for trades and time-limited authorizations.

### 2. Privacy: EIP-8182
**What happened**
- [EIP-8182: update](https://github.com/ethereum/EIPs/pull/11671) (RogerPodacter), submitted and merged. EIP-8182 defines protocol level private ETH and ERC-20 transfers.
- [aztecnetwork: AI proofs verified using the UltraHonk proving scheme](https://x.com/aztecnetwork/status/2055318449564573987), 23:04.
- [Eli Ben-Sasson: the lack of privacy is a real barrier to mass adoption, like clunky UX or limited scalability](https://x.com/EliBenSasson/status/2055252632579490052), 18:43.

**Why it matters**
- For privacy: protocol level private transfers do not depend on one application's privacy pool; all users share one mechanism, so the anonymity set is not split across apps.
