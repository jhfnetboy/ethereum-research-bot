## Key topics

### 1. Privacy: an enshrined privacy pool
**What happened**
- [Add EIP: Private ETH and ERC-20 Transfers](https://github.com/ethereum/EIPs/pull/11373) (RogerPodacter), submitted: a protocol enshrined privacy pool system contract defining a canonical validity layer for private ETH and ERC-20 transfers with public deposits and withdrawals, a fixed address, hard fork only upgrades, no admin or proxy keys and a shared note tree; [Magicians thread EIP-8182](https://ethereum-magicians.org/t/eip-8182-private-eth-and-erc-20-transfers/27889), 03:15.
- [Magicians: Draft ERC Private ERC-1155](https://ethereum-magicians.org/t/draft-erc-private-erc-1155-privacy-preserving-multi-token-standard/27894), 17:59; [aztecnetwork: the updated Aztec product roadmap, with all code complete to build privacy preserving contracts on Ethereum](https://x.com/aztecnetwork/status/2029229991188443353), 23:18.

**Why it matters**
- For privacy: an enshrined pool concentrates the anonymity set in one contract no admin can change, easing the small sets that come from fragmented pools.

### 2. Transaction privacy: LUCID
**What happened**
- [Add EIP: LUCID encrypted mempool](https://github.com/ethereum/EIPs/pull/11376) (anderselowsson), submitted; since ACDE #231 on February 26 LUCID has been the only encrypted pool headliner proposal.

### 3. Accounts and post-quantum
**What happened**
- [ethresear.ch: Achieving Quantum Safety Through Ephemeral Key Pairs and Account Abstraction](https://ethresear.ch/t/achieving-quantum-safety-through-ephemeral-key-pairs-and-account-abstraction/24273) (mvicari), 17:24: with no change to signature schemes or protocol rules, account abstraction makes each ECDSA key single use, rotating the signer every transaction while the smart wallet address stays constant.
- [EIP-8130: update verifier gas and cross chain sigs](https://github.com/ethereum/EIPs/pull/11374) (chunter-cb), submitted; [EIP-8130: revisions](https://github.com/ethereum/EIPs/pull/11367) (chunter-cb), merged; [EIP-8130: update motivation](https://github.com/ethereum/EIPs/pull/11372) (chunter-cb), submitted and merged.

**Why it matters**
- For accounts: a public key is exposed only when signing, so single use keys leave a quantum attacker no time, provided the user is already in a smart account, which is where native AA and the PQ roadmap meet.
