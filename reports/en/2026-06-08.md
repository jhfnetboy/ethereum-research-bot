## Key topics

### 1. EIP-7702 authorization gas under EIP-8037
**What happened**
- [EIP-8037: unfair allocation of EIP-7702 overcharges](https://github.com/ethereum/EIPs/pull/11778) (lu-pinto), submitted. In EIP-8037, worst cases are charged for 7702 authorization processing before the authorizations are processed, so users must commit much more gas than they need; this prevents compute griefing. But when the overcharge is corrected during delegation processing, it goes to the state gas pool or the refund counter and can no longer be used for compute.
- [EIP-8037: remove CALLCODE from the account creation cases](https://github.com/ethereum/EIPs/pull/11759) (rjl493456442), merged. CALLCODE runs in the caller's own account context and only transfers value to the caller itself, so it cannot create an account.

**Why it matters**
- For wallets using 7702: transactions with authorization lists must reserve gas for the worst case, and if the corrected part cannot be used for execution, complex batched calls are more likely to run short, which wallet gas estimation has to account for.

### 2. Post-quantum consensus and block building
**What happened**
- [New EIP: Post-Quantum Attestation Aggregators](https://github.com/ethereum/EIPs/pull/11777) (anshalshukla), submitted, describing how aggregators collect signed validator attestations and prove the attached post-quantum signatures into succinct aggregate proofs.
- [ethresear.ch: Trustless payments and relays](https://ethresear.ch/t/trustless-payments-and-relays/25125), 22:01 (jcschlegel). ePBS adds an in-protocol, sealed-by-default first-price channel for builder to proposer payments; the authors expect relays to survive but with a different offering, and predict that trustless in-protocol payments will ossify a first-price block auction and push it toward sealed bids.
- [ethresear.ch: Hot-Cold Storage Separation in Practice](https://ethresear.ch/t/hot-cold-storage-separation-in-practice/25119), 11:19 (weiihann). EIP-8188 adds a consensus-visible last-modified timestamp to every account and storage slot, giving all clients the same signal about which state is hot and which is cold; the EIP itself mandates no storage architecture.
- Per Ethereal news #27, ACDT #82 (21:00, with execution and consensus layer breakouts): the EIP-7997 deterministic factory switched from a predeploy to an enshrined Arachnid factory.

**Why it matters**
- For accounts and apps: a deterministic factory decides whether smart accounts can be deployed at the same address across chains, and using the widely used Arachnid factory stays compatible with existing deployment tooling.
