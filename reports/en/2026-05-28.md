## Key topics

### 1. Privacy: the Interfold and anonymity sets
**What happened**
- [Vitalik: more people should know about the Interfold; it is basically what he has been urging people to build with the MACI ideas for almost a decade, now in a generalized form, a privacy protocol optimized for things like voting](https://x.com/VitalikButerin/status/2059962457297215563), 18:38.
- [auryn_macmillan: the idea for the Interfold came from his unease at being the MACI coordinator for several clrfund rounds; MACI's privacy relies on an honest coordinator assumption](https://x.com/auryn_macmillan/status/2060002604051005574), 21:17.
- [AndyGuzmanEth: is anyone working on unifying anonymity sets in heterogeneous systems, such as Tornado Cash, Railgun and Privacy Pools?](https://x.com/AndyGuzmanEth/status/2059771512865874251), 05:59.
- [EliBenSasson: privacy tech is often not understood in its nuances; better privacy does not necessarily mean "more private"](https://x.com/EliBenSasson/status/2059966718408020462), 18:55.

**Why it matters**
- For privacy: removing the trust assumption that a single coordinator sees every vote is key to making MACI style apps credible, and because anonymity sets are split across protocols, each pool is smaller; unifying them would directly raise every user's privacy.

### 2. Transactions and gas: data floor pricing
**What happened**
- [EIP-8131: rewritten as a Unified Transaction Content Floor](https://github.com/ethereum/EIPs/pull/11738) (nerolation), submitted: prepared for Hegotá, it adds blob versioned hashes, generalizes the target to user controlled bytes and updates the impact analysis.
- [New EIP: Block Access List Byte Floor](https://github.com/ethereum/EIPs/pull/11739) (nerolation), submitted: adds BAL data to the EIP-7623 calldata floor pricing to cut worst case block size with minimal impact on users.

**Why it matters**
- For users: ordinary transactions are barely affected, and the main constraint falls on transactions built to stuff in data; smaller worst case blocks leave room to keep raising the gas limit safely.

### 3. Accounts: native AA on Aztec
**What happened**
- [aztecnetwork: every account on Aztec is a smart contract, with no EOAs and no bolt-on abstraction layers; authentication runs on the device and the sequencer only verifies a fixed size proof, so a multisig costs the same as a single signature](https://x.com/aztecnetwork/status/2059779182142595098), 06:30.
- [Magicians: ERC-8299 WYRIWE (What You Read Is What You Execute)](https://ethereum-magicians.org/t/erc-8299-wyriwe-what-you-read-is-what-you-execute/28655), 18:06 (TMerlini), defining a triple hash commitment and an EIP-712 attestation profile for AI inference input provenance.

**Why it matters**
- For accounts: replacing onchain signature checks with a proof means complex account policies no longer pay gas per signature, a useful reference for native AA design on Ethereum.
