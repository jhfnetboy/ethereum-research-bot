## Key topics

### 1. EIP-8141 rules beyond the mempool
**What happened**
- [EIP-8141: frame-aware inclusion list (FOCIL) validity](https://github.com/ethereum/EIPs/pull/12086) (Marchhill), submitted. It requires EIP-7805 inclusion list validity checks to evaluate a frame transaction's validation prefix instead of its nonce and balance, and adds `MAX_IL_VERIFY_GAS`.
- [EIP-8141: specify block inclusion gating and payer solvency](https://github.com/ethereum/EIPs/pull/12091) (AnkushinDaniil), submitted. The PR notes two facts that are only implied today: the block gas reservation is `max_gas`, and solvency belongs to `payer`, which appears only in the Mempool section that a block builder is not required to follow; an implementation reusing its existing transaction selection path inherits the resulting defects.
- [donnoh: a proposal for native rollups via STARK-carrying frame transactions (8141 + 8288)](https://x.com/donnoh_eth/status/2084644526828761203), 21:16. With a registry, native rollups can enforce proofs that follow L1 semantics and either upgrade automatically with L1 or pin a specific fork.

**Why it matters**
- Paymasters are a core use of frame transactions. A builder that checks only the sender's balance could include a transaction its payer cannot afford; writing the rule into the spec gives clients and builders consistent behavior. Whether FOCIL can force inclusion of frame transactions decides whether native AA transactions get the same censorship resistance.

### 2. Glamsterdam storage access pricing
**What happened**
- [EIP-2780: revise COLD_STORAGE_ACCESS and ACCOUNT_WRITE values](https://github.com/ethereum/EIPs/pull/12083) (misilva73), merged. Per the PR, EIP-8038 sets `COLD_STORAGE_ACCESS` to 2,100 (unchanged from today) and `ACCOUNT_WRITE` to 9,000, and recomputes `CREATE_ACCESS`, `STORAGE_CLEAR_REFUND` and `ACCESS_LIST_STORAGE_KEY_COST`.
- [EIP-2780: align runtime charging and reference cases](https://github.com/ethereum/EIPs/pull/12080) (spencer-tb), submitted. The text exempted self-transfers from all runtime recipient charges, contradicting the EIP's own "ETH transfer to self, sender 7702 delegated" reference row and the implementations, which all charge the delegation-target access.

**Why it matters**
- For wallets and RPCs: after Glamsterdam the gas for plain transfers and storage writes changes, and a self-transfer from a 7702-delegated account also pays the delegation-target access, so gas estimation must follow the new schedule.

### 3. EIP-8363 tapered issuance burn
**What happened**
- [Magicians: EIP-8363 Tapered Issuance Burn](https://ethereum-magicians.org/t/eip-8363-tapered-issuance-burn/29263), 16:30 (pintail), with [PR 12081](https://github.com/ethereum/EIPs/pull/12081). It modifies the issuance curve by partly burning validator rewards, with the per-duty burn design credited to Anders Elowsson. Per Ethereal news #34, net staking yield tapers linearly to zero at a 50% staking ratio, phased in over 18 months after the upgrade.

**Why it matters**
- This is an issuance proposal for Hegotá, and it set off a large debate this week; see August 5.
