## Key topics

### 1. Native AA: guarantors and the sighash in EIP-8141
**What happened**
- **Native Account Abstraction #1** took place ([agenda](https://ethereum-magicians.org/t/native-account-abstraction-1-april-22-2026/28227)).
- [EIP-8141: add support for guarantors](https://github.com/ethereum/EIPs/pull/11555) (derekchiang), submitted as a draft for early feedback: a guarantor is a payer that pays for the transaction even if sender validation fails, so as long as a transaction has a guarantor, mempool nodes need not check whether sender validation passes.
- [EIP-8141: mix the transaction type into the sighash](https://github.com/ethereum/EIPs/pull/11544) (derekchiang), merged; submitted on April 18.
- [lightclients: en route to 2M MAU of 7702](https://x.com/lightclients/status/2046955885763998023), 21:14; [EIP-2780: clarify interactions with EIP-7702 and EIP-7928](https://github.com/ethereum/EIPs/pull/11332) (gurukamath), merged.

**Why it matters**
- For accounts: the hardest problem with arbitrary validation logic is mempool DoS, since nodes must run validation to learn whether a transaction will pay; a guarantor separates "who pays" from "does validation pass", so nodes only check the guarantor's funds, which is what lets complex account transactions enter the public mempool safely.

**Why it matters**
