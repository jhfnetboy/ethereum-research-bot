## Key topics

### 1. Calls: ACDE #228
**What happened**
- [ACDE #228](https://forkcast.org/calls/acde/228), 21:00, per [Ethereal news #7](https://ethereal.news/ethereal-news-weekly-7/): Glamsterdam targets June 2026; [EIP-7954](https://forkcast.org/eips/7954/), raising the contract size limit to 32KiB, is CFI; the [EIP-8037](https://forkcast.org/eips/8037/) state creation gas increase goes to the next ACDT; EIP-7793 conditional transactions, the EIP-5920 PAY opcode, the EIP-8051 ML-DSA verification precompile, EIP-7971, EIP-8032, EIP-7907 and EIP-7903 were declined; see also [poojaranjan19's recap](https://x.com/poojaranjan19/status/2011833637369757829), 23:11.

**Why it matters**
- For accounts and signatures: with the ML-DSA precompile declined, smart accounts doing post-quantum verification in Glamsterdam must still do it in contract code at higher cost.

### 2. Transactions: simulation for wallet safety
**What happened**
- [ethresear.ch: Trust minimized transaction simulation using state proofs](https://ethresear.ch/t/trust-minimized-transaction-simulation-using-state-proofs/23857) (Sednaoui), 14:54: simulation is critical to wallet safety but today relies on blindly trusting RPC state, so the post uses MPT proofs and multi node consensus to verify the state behind simulations.

**Why it matters**
- For transactions: if an RPC tampers with what users preview before signing, they sign malicious transactions, and verifiable simulation removes that single point of failure.
