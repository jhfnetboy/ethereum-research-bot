## Key topics

### 1. Privacy: protocol level privacy pools and confidential tokens
**What happened**
- [StarkWare: native privacy for all assets is live on Starknet; STRK20s are fully live on mainnet, a privacy pool integrated at the protocol level](https://x.com/StarkWareLtd/status/2073088809030320488), 23:57, claiming the lowest privacy fee on the market and one click UX.
- [New ERC: Notary-Backed Confidential Token](https://github.com/ethereum/ERCs/pull/1850) (awrichar), submitted as ERC-8322: a confidential token interface using private state commitments, with state transitions pre-validated by a notary or notary group.
- [ethereum: Proton Mail inspires the broader privacy movement with encrypted web tools for everyone](https://x.com/ethereum/status/2073043680353497435), 20:58. [EFDevcon: privacy is not a feature, it is a principle, Devcon 8 Mumbai](https://x.com/EFDevcon/status/2072842140279853274), 07:37.

**Why it matters**
- For privacy: with the privacy pool integrated at the protocol level, all kinds of assets can use the same privacy infrastructure, which gives the anonymity set a chance to grow, and the larger the set the harder it is to link a single transaction. ERC-8322 takes another route, with a notary validating private state transitions offchain; the trust assumptions differ and it suits assets that need compliance review.

### 2. Account transactions and gas: EIP-8037
**What happened**
- [EIP-8037: charge account creation conditionally at access](https://github.com/ethereum/EIPs/pull/11858) (chfast), submitted: instead of charging unconditionally and refilling, CREATE/CREATE2 charge at the single destination access that also performs the EIP-7610 collision check; creations failing the balance, nonce or depth checks never read the destination and charge nothing, and pre-existing destinations such as pre-funded deterministic deployment addresses charge nothing.
- [EIP-7997: add EAS-like bytecode, treating the factory contract as a system contract](https://github.com/ethereum/EIPs/pull/11856) (jochem-brouwer), submitted, matching the system contract approach of EIP-7002 and EIP-7251.

**Why it matters**
- For accounts: contract accounts and smart wallets are deployed through CREATE/CREATE2, so conditional charging means failed deployments and accounts that already exist at counterfactual addresses no longer pay state gas for nothing, making deployment costs more predictable.

### 3. Consensus and execution merges
**What happened**
- [New EIP: Builder Execution Requests](https://github.com/ethereum/EIPs/pull/11760) (wemeetagain), merged as EIP-8282: it gives EIP-7732 (ePBS) builders their own execution layer request contracts on the EIP-7685 request bus instead of routing builder onboarding and exit through validator flows; [EIP-8282: sync with the gloas spec](https://github.com/ethereum/EIPs/pull/11859), submitted, changing the prefix to `0xB0` and adding a balance check.
- [New EIP: Multi-block Access List Warming](https://github.com/ethereum/EIPs/pull/11776) (nerolation), merged as EIP-8289: a 256-block rolling warm access multiset, committed via a SHA-256 SMT root in the block header, carries the EIP-2929 access list across blocks, for about a 14% median gas saving per block at about 10 MB of node state.
- [New EIP: Batching Attestations at Source](https://github.com/ethereum/EIPs/pull/11589) (raulk), merged.
