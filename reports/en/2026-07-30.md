## Key topics

### 1. ACDE #242 and Hegotá candidates
**What happened**
- Per Ethereal news #33, ACDE #242 (21:00): Platåberget is a short-lived permissionless public testnet targeting early August, with repricing numbers updated from benchmarks and discv5-only execution layer discovery. Non-headliner Hegotá proposals (deadline August 6) include Etan Kissling's EIP-8115 batch priority fees at end of block, EIP-8116 replacing cumulative receipt fields and EIP-7807 SSZ execution blocks (a scaled-down headliner proposal); Derek Chiang's (ZeroDev) EIP-7819 SETDELEGATE instruction; Alex Forshtat's EIP-7906 transaction assertions via a state diff opcode; Jochem Brouwer's EIP-7668 removing bloom filters; and Kev Wedderburn's EIP-8200 EVMification and EIP-7666 EVM-ify the identity precompile. The polar bear beat the flamingo as Glamsterdam mascot.
- Merged into EIP-8081: [EIP-8115](https://github.com/ethereum/EIPs/pull/11911), [EIP-8116](https://github.com/ethereum/EIPs/pull/11912), [EIP-7807](https://github.com/ethereum/EIPs/pull/11913), and [EIP-7906 as PFI](https://github.com/ethereum/EIPs/pull/12013). Also submitted: [EIP-7668 as PFI](https://github.com/ethereum/EIPs/pull/12046) (jochem-brouwer) and [proposing EIP-8333 for inclusion](https://github.com/ethereum/EIPs/pull/12044) (wemeetagain).
- [EIP-7906: rephrase the deploy frame side effects security consideration](https://github.com/ethereum/EIPs/pull/12030) (forshtat), submitted and merged; [EIP-8200: remove BLS map precompiles](https://github.com/ethereum/EIPs/pull/12031) (kevaundray), submitted and merged.

**Why it matters**
- For wallets: 7819 and 7906 are both account-layer proposals that, with 8141, shape the Hegotá account experience; 7906 lets a transaction assert on its post-execution state diff and fail if it does not match, serving trustless clear signing.

### 2. EIP-8141 paymaster and 8250 concurrency
**What happened**
- [EIP-8141: assembled canonical paymaster reference bytecode](https://github.com/ethereum/EIPs/pull/12041) (Marchhill), submitted, continuing #12012: a 355-byte runtime implementing dispatch, payment validation, deposit and four timelocked admin operations (withdrawal/rotation initiate, cancel, finalize), plus a keccak256 code hash as the per-fork recognition anchor.
- [EIP-8141: align SIGPARAM copy operand order with CALLDATACOPY](https://github.com/ethereum/EIPs/pull/12042) (Marchhill), submitted.
- [EIP-8250: define keyed mempool concurrency](https://github.com/ethereum/EIPs/pull/12039) (soispoke), submitted: 8250 gives frame transactions independent replay domains, but the mempool kept 8141's limit of one pending frame transaction per sender; the PR defines a narrow optional exception, with key zero and transactions with mutable validation dependencies still under the sender limit.

**Why it matters**
- For paymasters and wallets: with deployable bytecode and a fixed code hash, nodes can admit canonical paymaster sponsored transactions quickly by code match, and keyed mempool concurrency means shared-sender designs no longer have to send transactions serially.
