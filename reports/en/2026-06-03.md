## Key topics

### 1. Native AA: EIP-7701 withdrawn, EIP-8130 tightened
**What happened**
- [EIP-7701: move to Withdrawn with a withdrawal reason](https://github.com/ethereum/EIPs/pull/11528) (forshtat), merged.
- [EIP-8130: resolve constants, gas accounting and interface cleanups](https://github.com/ethereum/EIPs/pull/11757) (chunter-cb), submitted and merged: sets `AA_TX_TYPE` (`0x7B`) and `AA_PAYER_TYPE` (`0x7C`), the nonce manager and transaction context precompile addresses, and declares every referenced EIP.
- [EIP-8130: define a signature invariant, nonce free replay identifier](https://github.com/ethereum/EIPs/pull/11752) (chunter-cb), merged; [EIP-8130: add existing account and code size guards to create entries](https://github.com/ethereum/EIPs/pull/11609) (pochenai), merged.
- [EIP-8130: minimize the Transaction Context precompile to identity](https://github.com/ethereum/EIPs/pull/11758) (chunter-cb), submitted.

**Why it matters**
- For accounts: EIP-7701 was the native AA design of the EOF era, and with it withdrawn the native AA field narrows to proposals such as EIP-8141 frame transactions and EIP-8130; filling in EIP-8130's type numbers and precompile addresses shows it moving from concept to an implementable spec.

### 2. Wallet signing safety
**What happened**
- [ERC: Clear Signing On-Chain Descriptors Registry](https://github.com/ethereum/ERCs/pull/1789) (forshtat), submitted: ERC-7730 descriptors are too big to store onchain, so the registry contract stores IPFS identifiers and EAS attestations instead of relying on GitHub as the registry.
- [ERC-7796: move to Review](https://github.com/ethereum/ERCs/pull/1692) (forshtat), merged.
- [ERC: Wallet-Scoped Token Pull Execution](https://github.com/ethereum/ERCs/pull/1790) (wenzhenxiang), submitted, with the [ERC-8284 discussion](https://ethereum-magicians.org/t/erc-8284-wallet-scoped-token-pull-execution/28691), 16:22.

**Why it matters**
- For users: Clear Signing has wallets render transactions in human readable form, and whether a descriptor's source is trustworthy decides whether the display can be trusted; an onchain registry with attestations makes that trust verifiable.

### 3. Transactions and building
**What happened**
- [New EIP: Builder Execution Requests](https://github.com/ethereum/EIPs/pull/11760) (wemeetagain), submitted: gives EIP-7732 (ePBS) builders dedicated deposit and exit request contracts on the EIP-7685 request bus instead of routing through validator flows.
- [EIP-8037: remove callcode from account creation cases](https://github.com/ethereum/EIPs/pull/11759) (rjl493456442), submitted.
