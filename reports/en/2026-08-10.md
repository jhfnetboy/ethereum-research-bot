## Key topics

### 1. Both native AA tracks move forward
**What happened**
- [EIP-8130: align with Keystore contract, transaction validity window, slim spec](https://github.com/ethereum/EIPs/pull/12135) (chunter-cb), submitted. The Account Configuration contract is renamed the Keystore contract (`KEYSTORE_ADDRESS`, `IKeystore`) and aligned with the canonical `base/eip-8130` implementation; contract internals such as storage layout, typehashes, event ABIs and function bodies are deferred to that repository, and the EIP keeps only the protocol consensus surface.
- [EIP-7906: specify handling of reserved "must be 0" inputs](https://github.com/ethereum/EIPs/pull/12132) (Marchhill), merged. Several `TXTRACE`/`TXDIFF` operands are marked must be 0, but the spec never said what happens on a non-zero value; since these run in a `POST_TX` frame, a divergence changes post-transaction state and so block validity, and the PR makes a non-zero value an exceptional halt. Also merged that day: [record TXDIFF state reads per EIP-7928](https://github.com/ethereum/EIPs/pull/12133) and [define contracts_deployed precisely](https://github.com/ethereum/EIPs/pull/12134).

**Why it matters**
- EIP-8130 (account configuration) and EIP-8141 (frame transactions) are the two candidates for native AA in Hegotá. Handing 8130's implementation to Base's canonical repository means the design now has an auditable contract implementation. EIP-7906 lets a transaction assert its state changes after execution, which wallets can use to stop results that differ from what the user expected.
