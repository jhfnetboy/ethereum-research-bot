## Highlights
1. **8130 security**: a PoC shows existing timelocked wallets' protection can be bypassed under 8130.
2. **Account authority**: a revoked authority is rejected no later than the next block; a `SLOTS16` recovery scheme and a cross-chain `SLOTS16_SYNC` scheme.
3. **EIP-8037**: two sibling calls are enough to strand execution gas in the reservoir.

## Key topics

### 1. Security boundaries of native AA
**What happened**
- [donnoh_eth: a minimal PoC bypassing a timelocked smart wallet's timelock using EIP-8130](https://x.com/donnoh_eth/status/2093407080581353796), 01:35, tested on Base testnet; before 8130 it cannot be bypassed.
- [New ERC: account authority lifecycle](https://github.com/ethereum/ERCs/pull/1979) (AnkushinDaniil), submitted. An account commits to its authorities as one root or keeps them as records; its authorization check accepts an authority only if it is in the current authority state and a witness covers the whole transaction, and a revoked authority is rejected no later than the next block. It gives a binding to EIP-8141 with a discovery interface (`authorityRoot`, `AuthorityStateChanged`), `SLOTS16`, a 16-slot recovery scheme, and `SLOTS16_SYNC` for the same account on another chain.
- [Frame Transaction Breakout #3 agenda](https://ethereum-magicians.org/t/frame-transaction-breakout-3-sep-1-2026/29539), 22:21, for September 1 at 21:00: client progress and AA proposal updates.

**Why it matters**
- For wallets: a new protocol-level authorization path changes the security assumptions of existing contract wallets, so timelocks, social recovery and other designs that assume a single authorization path need review. This is exactly the kind of issue the AA breakouts must handle while converging 8141 and 8130.

### 2. Gas accounting
**What happened**
- [EIP-8037: return state gas to gas_left when a child merges](https://github.com/ethereum/EIPs/pull/12265) (chfast), submitted. `state_gas_from_gas_left` is frame-local while a slot's original value is its value at transaction start, so the refilling frame need not be the charging frame: with the reservoir empty, a first call's `SSTORE` to a fresh slot spills 97,920 from `gas_left`, a second call clears the slot, and the credit lands in the reservoir, the shape an ERC-4337 bundle takes.
- gcolvin merged [extensive work on EIP-8337 definitions, constraints, validation and code](https://github.com/ethereum/EIPs/pull/12262), [an EIP-7979 cleanup](https://github.com/ethereum/EIPs/pull/12263) and [consistent EIP-8173 terminology](https://github.com/ethereum/EIPs/pull/12264).

**Why it matters**
- For bundlers: execution gas stuck in a state-only reservoir means a bundle has less usable gas than expected, so simulation and estimation must follow the corrected rules.
