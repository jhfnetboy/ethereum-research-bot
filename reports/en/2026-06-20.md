## Key topics

### 1. Data pricing
**What happened**
- [New EIP: Increase Calldata Floor Cost to 96](https://github.com/ethereum/EIPs/pull/11821) (misilva73), submitted, raising the calldata floor from 64/64 to 96/96 gas per byte. The motivation is that the 21,000-gas ETH transfer anchors both the execution and bandwidth dimensions of a block, and a block full of transfers has an irreducible byte density of about 0.0105 bytes per gas.
- [EIP-8279: explicit BAL data metering with net-zero refund](https://github.com/ethereum/EIPs/pull/11819) (misilva73), submitted. BAL bytes are metered in a per-transaction `bal_data_bytes` counter that only feeds the floor, with no new gas dimension and the same `max(execution, floor)` charge; a slot restored to its pre-transaction value (O→X→O) costs nothing, and repeated distinct writes (A→B→C) count once.

**Why it matters**
- For AA transactions: the calldata floor only applies when a transaction has a lot of data and little compute, so transactions with large signatures (such as post-quantum ones) or large batched call data are the most likely to hit it, and a higher floor directly affects their cost.

### 2. Post-quantum keys
**What happened**
- [New EIP: Post-Quantum Keystore for Stateful Keys](https://github.com/ethereum/EIPs/pull/11820) (ch4r10t33r), submitted, defining a keystore format for stateful hash-based signing keys such as the XMSS used by the lean Ethereum consensus layer. It extends EIP-2335 so the encrypted secret may be an XMSS seed, and adds the machinery a consumable key requires.
- [StarkWare: a vote on two new Starknet v0.14.3 optimizations for EVM privacy and quantum security is live](https://x.com/StarkWareLtd/status/2068274401187905881), 17:06, ending June 26. [StarkWare: anyone can shield their entire onchain activity in a few clicks](https://x.com/StarkWareLtd/status/2068303271677112734), 19:01.

**Why it matters**
- For validators: each one-time key in a stateful signature scheme can be used only once, and reuse leaks the private key, so the keystore must track which positions are used, and mistakes in migration or backup are very costly.
