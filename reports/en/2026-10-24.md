# Ethereum Research Daily 2026-10-24

Keywords: EIP-8037 fix, legacy share, RESERVOIR opcode, EIP-8053 gas units at the contract boundary, EIP-8425 quantum freeze and account recovery

Summary: Two days after the ChainSecurity report, a fix took shape. A PR from LukaszRozmej credits state gas refills and rollbacks only to the reservoir, so `gas_left` never increases within a frame, and adds a legacy share so a new storage slot still costs its Osaka price in execution gas; the same mechanism goes into EIP-8141. Another PR proposes a RESERVOIR opcode so contracts can see the reservoir balance. EIP-8425 quantum freeze and account recovery was merged as a draft.

## Highlights
1. **EIP-8037 fix**: refills and rollbacks credit only the reservoir, and the caller gets back only the child's unused `gas_left`; the legacy share means a new cold slot still takes 22,100 from `gas_left`.
2. **Frame transactions follow**: an EIP-8141 PR charges the legacy share in frame transactions too.
3. **Observability**: a RESERVOIR (0x4d) proposal lets contracts read the state gas balance that `GAS` does not show, and an EIP-8053 PR keeps contracts seeing gas rather than milli-gas.
4. **Quantum readiness**: EIP-8425 quantum freeze and account recovery was merged, with the semantics of calling `ecRecover`'s old address after its removal spelled out.

## Key topics

### 1. Patching EIP-8037's gas flowback
**What happened**
- [PR 12581: credit state gas refills to the reservoir and add a legacy share](https://github.com/ethereum/EIPs/pull/12581) (LukaszRozmej, editing both EIP-8037 and EIP-2780) targets the problems in the ChainSecurity article:
  - Refills and frame rollbacks credit only the reservoir, never `gas_left`, so `GAS` never increases within a frame and a call returns at most the child's unused `gas_left`. Clearing a new slot or a reverting intermediary no longer hands execution gas to the caller.
  - Legacy share: a state gas charge first takes `min(state_gas_charge, max(0, PRE_FORK_COST - execution_gas_charge))` from `gas_left`, using the fixed Osaka costs of 20,000 (storage), 25,000 (new account) and 32,000 (CREATE). With current EIP-8038 values that is 10,000 for a new slot, so a cold new slot still takes 22,100 from `gas_left` in total, the same as Osaka.
  - The fourth problem is only partly addressed: EIP-8038's increases and state creation in transactions without a reservoir can still exceed old budgets.
- [EIP-8141: charge the EIP-8037 legacy share as extra execution gas](https://github.com/ethereum/EIPs/pull/12583) (LukaszRozmej); otherwise a callee in a frame transaction could write a cold new slot with about 12,100 execution gas.
- [New EIP: RESERVOIR opcode](https://github.com/ethereum/EIPs/pull/12577) (ja7ad), 0x4d, returning the current frame's `state_gas_reservoir` (the remaining `state_gas_left` in frame transactions); used with `GAS`, it lets contracts measure net consumption including state gas.
- [EIP-8053: gas units at the contract boundary](https://github.com/ethereum/EIPs/pull/12584) (LukaszRozmej). The draft had `GAS` return milli-gas while call arguments and the stipend stayed in gas, which would make code like `gasleft() - 5000` or `gasleft() < x / 63` off by a factor of 1000; after the change, milli-gas stays inside the EVM.

**Why it matters**
- The fix aims to make two old assumptions true again, that spent gas does not come back and that creating state does not get cheaper in execution gas, so individual contracts would not need upgrades. For contract teams, this is the key precondition for rescheduling Hoodi and worth tracking; contracts that need precise gas measurement could later use RESERVOIR.

### 2. Quantum freeze and account recovery
**What happened**
- [New EIP: quantum freeze and account recovery](https://github.com/ethereum/EIPs/pull/12383) was merged (colinlyguo, EIP-8425), proposing a minimal framework for freezing legacy ECDSA authorization and recovering unmigrated accounts, building on a Magicians discussion about freezing and recovery for Q-day.
- [EIP-8425: clarify ecRecover removal semantics](https://github.com/ethereum/EIPs/pull/12580) was merged, defining account state, ordinary call semantics, empty return data and EIP-2929 access accounting for calls to the old address; [clarify recovery scope and account access rules](https://github.com/ethereum/EIPs/pull/12585) was also merged.

**Why it matters**
- This complements bunker mode: after a practical quantum break, stopping forged contract-level authorizations takes priority over compatibility. Contracts that verify signatures with `ecrecover`, such as permits and meta-transactions, should prepare migration paths early.
