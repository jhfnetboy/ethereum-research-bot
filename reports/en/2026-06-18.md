### 2. The EIP-8130 storage model and EIP-8141 cleanup
**What happened**
- [EIP-8130: fold default EOA revocation into a state flag](https://github.com/ethereum/EIPs/pull/11815) (chunter-cb), submitted and merged. It removes the `REVOKED_AUTHENTICATOR` sentinel: revoking the implicit EOA actor used to mean overwriting its `actor_config` slot with the magic address `type(uint160).max`; now a state flag represents it and the secp256k1 authentication path is unified, with no wire format change and a safer default.
- [EIP-8130: store the self-actor secp256k1 config inline in the account state slot](https://github.com/ethereum/EIPs/pull/11816), submitted and merged. The default EOA's `scope`, `policyType` and `expiry` live in the same 32-byte account state slot as `DEFAULT_EOA_REVOKED`, so the account's own key, including a scoped self, resolves in a single SLOAD.
- [EIP-8141: spec cleanup and clarifications](https://github.com/ethereum/EIPs/pull/11814) (morph-dev), submitted: `sig.signer` may be empty and defaults to `tx.sender`; raw `sig.signature` bytes are left out of every `sig_hash`, since all signatures must be valid for the transaction to be valid, committing to `sig.msg` already commits to the signatures indirectly, and including them would block future signature aggregation; the mempool section covers the expiry verifier frame and more.

**Why it matters**
- For EOA migration: in 8130 the original EOA key is a default actor, and revoking it leaves the account controlled only by new keys; a state flag is less error-prone than a magic value. Keeping signature bytes out of the 8141 hash leaves room for post-quantum signature aggregation (such as EIP-8288).

### 3. Network layer privacy
**What happened**
- [pcaversaccio: leaking metadata such as IP, user-agent, timezone and language settings can fully destroy onchain privacy](https://x.com/pcaversaccio/status/2067323271436177600), 02:07; using Tor also makes it easy to fingerprint you as a Tor user, and Ethereum needs its own native browser. He then posted [Etherveil, an Ethereum privacy browser, on ethresear.ch](https://ethresear.ch/t/etherveil-an-ethereum-privacy-browser/25224), 16:14, based on Firefox/Gecko and Tor Browser; it is an early architectural proposal seeking feedback.
- [kassandraETH: what if way more people used Tornado Cash, as basic onchain privacy hygiene, to grow the anonymity set, and as a default wallet standard](https://x.com/kassandraETH/status/2067590873886466215), 19:50.
- [StarkWare: Starknet v0.14.3 adds Keccak support for client-side proving, enabling virtual private transactions signed with EVM signatures, and a quantum-resistant SNOS hash with Blake replacing Pedersen](https://x.com/StarkWareLtd/status/2067610980876529744), 21:10.

**Why it matters**
- For privacy: onchain privacy protocols only protect the transaction graph, and metadata leaked at the RPC and browser layer can link identities just as well. This is an often overlooked layer of privacy infrastructure.
