## Key topics

### 1. Accounts: sponsored transactions and native keys
**What happened**
- [New EIP: Contract Payer Transaction (EIP-8223)](https://github.com/ethereum/EIPs/pull/11509) (benaadams), submitted: a Core EIP for a sponsored transaction type where gas fees are charged to the target contract `tx.to` via a canonical payer registry predeploy; [Magicians discussion](https://ethereum-magicians.org/t/eip-8223-contract-payer-transactions/28202), 12:38.
- [EIP-8164: replace Ed25519 with ML-DSA-44 (FIPS 204)](https://github.com/ethereum/EIPs/pull/11511) (prestwich), submitted and merged: native key delegation for EOAs now uses the NIST standardized post-quantum scheme, with key sizes, signature sizes and precompile gas updated to match.
- [EIP-7932: add support for public key and signature separation](https://github.com/ethereum/EIPs/pull/11357) (SirSpudlington), merged: secp256k1 moves to algorithm type `0x0`, types above 126 are restricted, `merge_detached_signature` is added and a public key collision with secp256k1 is fixed.

**Why it matters**
- For accounts: letting a contract pay gas for its callers is a native sponsorship path that needs no bundler or relayer; EIP-8164 and EIP-7932 prepare the protocol level algorithm registry and key delegation for EOAs moving to post-quantum signatures.

### 2. The direction of account abstraction
**What happened**
- [gakonst: "just one more AA EIP" will not fix wallets; the Ethereum ecosystem must make some decisions for its wallet users, enforce them in an EIP instead of "infinite garden, anyone can build anything", and build actually good UX and DX](https://x.com/gakonst/status/2042685087775625521), 02:24.
- [gakonst: the upcoming Tempo T3 upgrade unlocks subscriptions and other account delegation primitives, upgrading access keys with native spend limits and scoping](https://x.com/gakonst/status/2042714867711586430), 04:22.

**Why it matters**
- For wallets: AA proposals keep multiplying, but user experience depends on wallets relying on one shared set of capabilities; access keys with spend limits and scoping are among the basics wallets need most.
