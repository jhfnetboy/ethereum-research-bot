## Key topics

### 1. Applications and charging on frame transactions
**What happened**
- [ERC-8339: Receiver-Attested Transfers](https://github.com/ethereum/ERCs/pull/1882) (muhammadaus), submitted; previously titled Two-Phase Asset Transfers, this revision removes the escrow, revoke/reclaim and secret-key flow. [Forum write-up](https://ethereum-magicians.org/t/erc-8339-receiver-attested-transfers/29017), 14:00: a transfer runs only if the receiver has signed consent for exactly that transfer, with no escrow, no second transaction and no pending state; it builds on EIP-8141 frame transactions and covers ETH and ERC-20/721/1155.
- [EIP-8272: restore EIP-8141 signature costs in tx_gas_limit](https://github.com/ethereum/EIPs/pull/11931) (AnkushinDaniil), submitted. As a delta on 8141, 8272 restated `tx_gas_limit` but dropped `signature_verification_cost` and the signatures' calldata cost, so post-fork frame transactions were under-charged for signatures. The same author also submitted [a fix for the TXPARAM_RECENT_ROOT_REFERENCE_COUNT value inconsistency](https://github.com/ethereum/EIPs/pull/11930): the constants table says `0x0F` while the TXPARAM table says `0x0D`.

**Why it matters**
- For wallets: frame transactions turn a "receiver consents first" flow that used to need an escrow contract into a single transaction, which can reduce mistaken transfers. For gas estimation: the 8272 fix decides how much gas frame transactions with recent root references actually pay.
