## Key topics

### 1. Transaction privacy: same slot decryption for LUCID
**What happened**
- [ethresear.ch: Same-Slot Decryption for LUCID, optional N execution with N+1 fallback](https://ethresear.ch/t/same-slot-decryption-for-lucid-optional-n-execution-with-n-1-fallback/24576) (murat), 00:26: LUCID decrypts in the slot after submission because the builder's commitment sits inside the beacon block and cannot be seen before the slot ends; builders must commit before seeing plaintext and decryptors must see the commitment before releasing keys, and the slot boundary breaks that loop at a cost of about 12 seconds, so the post proposes optional same slot execution.

**Why it matters**
- For transactions: waiting an extra slot pushes time sensitive trades back to the public mempool, so same slot execution narrows the cost of using encryption.
