## Highlights
1. **Keyed nonce pricing**: creating a keyed nonce under EIP-8250 no longer takes 20,000 execution gas; it now costs 97,920 state gas.
2. **Recent roots**: EIP-8272 carries up to 16 roots in a VERIFY frame that the public mempool can evaluate directly, outside `MAX_VERIFY_GAS`.
3. **EIP-8037**: a PR proposed documenting that `GAS` can increase within a frame, the point that later became the core of ChainSecurity's report.
4. **Private identity**: ProveKit v1 launched, aiming to prove a passport on a phone in under a minute with no trusted setup.

## Key topics

### 1. Gas and validation rules for frame transactions
**What happened**
- [EIP-8250: charge keyed nonce first use as state gas](https://github.com/ethereum/EIPs/pull/12279) was merged (soispoke). EIP-8141 gives each frame separate execution and state gas budgets, while EIP-8250 still charged 20,000 from the approving frame's execution gas. The charge now comes from `state_gas_left`, priced at EIP-8037's cost for one new storage slot, `STATE_BYTES_PER_STORAGE_SET * CPSB` (currently 97,920), since each fresh key creates one ordinary persistent slot.
- [EIP-8272: verify recent roots with a canonical frame](https://github.com/ethereum/EIPs/pull/12281) (soispoke). The `recent_root_references` field is replaced by a `VERIFY` frame that calls the recent root contract with up to sixteen `(source_id, slot, root)` tuples, placed before application validation. Public mempool validation allows only `SLOTNUM` and the required recent root storage reads, and the frame does not count toward `MAX_VERIFY_GAS`, leaving that budget for signature checks.
- [EIP-8037: note that gas_left can increase within a frame](https://github.com/ethereum/EIPs/pull/12285) (spencer-tb) added only a security consideration, without changing semantics, stating that `GAS` is no longer monotonic; the PR was eventually closed without merging.
- [EIP-8141: remove a redundant check for a frame's state gas limit](https://github.com/ethereum/EIPs/pull/12276), merged; [VOPS Profiles for FOCIL Eligibility](https://github.com/ethereum/EIPs/pull/12110), merged, defining two VOPS profiles for FOCIL, with profile 2 adding bounded validation replay for eligible frame transactions.

**Why it matters**
- With keyed nonces charged as state gas, the first AA transaction on a new key gets noticeably more expensive while reuse stays cheap, so wallets must tell first use from reuse when estimating gas. The one line about non-monotonic `GAS` turned out, a month later, to affect existing contracts.

### 2. Privacy and faster confirmation
**What happened**
- [recmo: ProveKit v1 is out](https://x.com/recmo/status/2095192675276173485), 23:50, letting developers build authentication with ZK privacy on all user devices; the goal is to show that an ordinary phone can ZK-prove a passport in under a minute, with no trusted setup and 128-bit post-quantum security.
- [EF: live session on Web3Privacy Now and its Privacy Explorer](https://x.com/ethereumfndn/status/2095152211026129071), 21:09.
- [binji: Ethlabs is pushing for adoption of FCR (the fast confirmation rule)](https://x.com/binji_x/status/2095073745115205773), 15:58, making moves between EVM chains and exchanges 60x faster.

**Why it matters**
- On-device ZK proofs make "prove you qualify without handing over your identity" possible on an ordinary phone, so wallets and apps can use them instead of collecting KYC documents.
