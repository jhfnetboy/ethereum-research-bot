## Key topics

### 1. Settling details in the native AA specs
**What happened**
- [EIP-8141: statically disallow approval scope on atomic-batch frames](https://github.com/ethereum/EIPs/pull/12109) (Marchhill), merged; see August 5 for the content.
- [EIP-8130: right-align address-derived actorIds](https://github.com/ethereum/EIPs/pull/12173) (chunter-cb), submitted and merged. Every address-derived `actorId` formula was written as the left-aligned `bytes32(bytes20(x))`, while the reference Keystore (`ActorId.fromAddress`) right-aligns as `bytes32(uint256(uint160(x)))`, with the address in the low 20 bytes.
- [EIP-8164: document effects on converted accounts](https://github.com/ethereum/EIPs/pull/12174) (nezu511), submitted. The four existing items explain why other accounts are unaffected, but the case named by the opening clause "unless the account owner explicitly converts" was not described anywhere; the PR fills it in with no normative change.

**Why it matters**
- For wallets and indexers: an `actorId` encoding that is off produces a different storage location, so only with spec and implementation aligned can third-party tools read an 8130 account's authority configuration correctly.
