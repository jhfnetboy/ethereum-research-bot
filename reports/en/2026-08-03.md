## Key topics

### 1. System contract addresses for keyed nonces and recent roots
**What happened**
- [EIP-8250: pin NONCE_MANAGER to 0x...8250](https://github.com/ethereum/EIPs/pull/12067) (AnkushinDaniil), merged. The PR explains that `NONCE_MANAGER`'s address determines the storage slots keyed nonces live in, so two clients that pick different values do not share a chain; the address was `0xTBD` while the contract code was already pinned. Both known implementations independently chose the address equal to the EIP number, matching the `EXPIRY_VERIFIER = 0x...8141` convention in EIP-8141.
- [EIP-8272: pin RECENT_ROOT_ADDRESS to 0x...8272](https://github.com/ethereum/EIPs/pull/12068) (AnkushinDaniil), merged the same day.

**Why it matters**
- Keyed nonces let one account use several nonce sequences in parallel, a basis for concurrent submission of privacy and native AA transactions. With the addresses in the spec, clients can build interoperable devnets from the spec alone instead of private agreements.

### 2. Using proofs to extend the mempool budget for frame transactions
**What happened**
- [EIP-8361: transaction validity proofs](https://github.com/ethereum/EIPs/pull/12075) (Marchhill), submitted. Per the PR, proofs of EIP-8141 validation prefixes raise the public mempool's validation-work ceiling and extend FOCIL eligibility without changing transaction execution or gas charges. It includes recursive batching, restricted fee-bump reuse, bounded certificate retrieval and one authenticated certificate per IL, and targets local consumer proving and future proof-verifying nodes.
- [New EIP: TCREATE opcode](https://github.com/ethereum/EIPs/pull/12073) (abc-123-c), submitted, a mechanism for deploying temporary contracts; [EIP-8081: PFI EIP-8360](https://github.com/ethereum/EIPs/pull/12074) was submitted the same day to propose it for Hegotá.

**Why it matters**
- When complex validation (for example a privacy proof) exceeds the mempool budget, the only route is a private channel. Replacing re-execution with a proof is one way to let such frame transactions propagate publicly.
