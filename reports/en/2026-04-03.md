## Key topics

### 1. Native AA: EIP-8141 signatures and verification
**What happened**
- [EIP-8141: add a signatures list to the outer tx](https://github.com/ethereum/EIPs/pull/11481) (lightclient), submitted: a key goal of 8141 is forward compatibility with signature aggregation, which may become crucial as many users migrate to large post-quantum signatures, so a signatures field is added to the outer transaction object.
- [EIP-8141: allow using precompiles for VERIFY frames](https://github.com/ethereum/EIPs/pull/11482) (derekchiang), submitted: previously only the EOA default code could, and the update lets EOAs and contract accounts share the same logic.

**Why it matters**
- For accounts and gas: moving signatures out of frames into an aggregatable outer list means post-quantum signatures from many transactions can later be verified together, sharply cutting per transaction gas and bandwidth.

### 3. Privacy: the zero knowledge property
**What happened**
- [ethbeat_org: most proving systems in the L2BEAT ZK Catalog lack the zero knowledge property and need extra work to hide private inputs](https://x.com/ethbeat_org/status/2040060468950188367), 20:34; [aztecnetwork: Aztec generates and proves transactions locally, so it really is ZK](https://x.com/aztecnetwork/status/2040111095546044847), 23:56.

**Why it matters**
- For privacy: rollup proofs used for scaling usually need only succinctness and do not hide inputs, so users should not equate ZK with privacy.
