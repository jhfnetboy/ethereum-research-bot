## Key topics

### 1. Native account abstraction: EIP-8141, EIP-8250, EIP-8130
**What happened**
- [New EIP: Keyed Nonces for Frame Transactions](https://github.com/ethereum/EIPs/pull/11598) (soispoke), merged as EIP-8250: one EIP-8141 sender can run multiple independent nonce sequences instead of a single linear queue, so trustless privacy protocols can send transactions concurrently.
- [EIP-8141: frames cleanup](https://github.com/ethereum/EIPs/pull/11621) (lightclient), merged. After two months of rapid spec changes, it improves readability without changing much functionality, and introduces a `skipped` receipt status `0x3` for frames skipped within a batch.
- EIP-8130: [move from to sender](https://github.com/ethereum/EIPs/pull/11526), merged; [add canonical verifier set](https://github.com/ethereum/EIPs/pull/11647) and [tighten verifier allowlist language](https://github.com/ethereum/EIPs/pull/11651) (chunter-cb), submitted and merged; [add owner call policies](https://github.com/ethereum/EIPs/pull/11648), submitted, using `policyType` and `policyTarget` to have the protocol enforce limits on owner calls.
- [EIP-8253: Bump nonce of zero-nonce storage accounts](https://ethereum-magicians.org/t/eip-8253-bump-nonce-of-zero-nonce-storage-accounts/28505), 16:20 (jochem-brouwer), an alternative to EIP-7610 that bumps the nonce of mainnet accounts with non-empty storage, zero nonce, no code and nonzero balance, removing the need for the EIP-7610 check.

**Why it matters**
- For privacy and accounts: many users of a privacy pool share one contract sender, and a single nonce queue makes their transactions block each other; keyed nonces let them be included in parallel. EIP-8130 owner call policies restrict at the protocol level what a key may call, a basis for session key style permissions.

### 2. Wallet security: clear signing
**What happened**
- [ethereumfndn: clear signing is now live, an open standard to end blind signing and make human-readable transactions the default](https://x.com/ethereumfndn/status/2054232916763263148), 23:11; [EF blog: clear signing announcement](https://blog.ethereum.org/en/2026/05/12/clear-signing-announcement).
- [ERC-8255: add a backwards compatibility section on breaking max approvals](https://github.com/ethereum/ERCs/pull/1739) (moodysalem), submitted and merged.

**Why it matters**
- For wallets: many thefts start with users unable to read what they sign; clear signing lets wallets display transaction intent from shared descriptors, a security upgrade at the signing layer.
