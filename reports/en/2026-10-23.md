## Key topics

### 1. After the postponement: second thoughts on EIP-8037/8038
**What happened**
- [Alex Stokes: core developers decided to delay the upcoming Hoodi hard fork on today's ACDE call](https://x.com/ralexstokes/status/2113327089306988960), 00:50; [EF: the Hoodi upgrade previously scheduled for October 26 has been delayed, new date TBA](https://x.com/ethereumfndn/status/2113652096717427132), 22:21.
- [EIP-7773: clear the postponed Hoodi activation](https://github.com/ethereum/EIPs/pull/12568) (ralexstokes), leaving Sepolia and mainnet content unchanged.
- [EIP-8037 PR: document gas returning before settlement and reservoir forwarding](https://github.com/ethereum/EIPs/pull/12573) (flcl42, a non-author addition). The current text only says that "a contract measuring work as the difference between two `GAS` reads then gets a negative value". The PR adds that clearing a slot created earlier in the transaction refills up to 97,920 gas into `gas_left` immediately, that reverts restore state gas accounting, and that the reservoir passes to child frames in full, so gas spent within a frame can come back before the transaction settles.
- [lightclient: personal retro, I really don't like these EIPs](https://x.com/lightclients/status/2113606207252611307), 19:19. They only let the gas limit increase without solving the fundamental problem of ever-growing state.

**Why it matters**
- The debate is moving from "where are the holes" to "is this the right path". The Glamsterdam mainnet date may slip as a result. Auditors can use the EIP-8037 security considerations being written as a checklist, and operators should watch for new Hoodi releases.

### 2. The frame transaction fee model
**What happened**
- [EIP-8141: use max_fee to bound cost](https://github.com/ethereum/EIPs/pull/12414) was merged (lightclient), adding `max_fee` to the frame object instead of per-dimension resource limits, adapted from EIP-7999.
- [EIP-8141: specify GASPRICE under the max_fee budget](https://github.com/ethereum/EIPs/pull/12569) was merged (spencer-tb). Unused gas can now back the tip, so the price per gas depends on `gas_used` and `GASPRICE` cannot be exact. It returns the lower bound `base_fee_per_gas + max_priority_fee // max_gas`, which is exact whenever `max_fee` covers the full tip and never above what the payer pays per gas, so gas refund contracts cannot be overpaid.
- [EIP-8141: move the mode section under the Frame definition](https://github.com/ethereum/EIPs/pull/12236), merged; [EIP-7906: remove the reference to txparam 0x06](https://github.com/ethereum/EIPs/pull/12576), merged.
- [ERC-7562: ban SLOTNUM](https://github.com/ethereum/ERCs/pull/2097) was merged, since like `BLOCKNUM` and `TIMESTAMP` it reads the environment.

**Why it matters**
- A single `max_fee` means wallets and sponsors only compute one cap. Contracts that use `GASPRICE` to reimburse gas need to know it is only a lower bound in frame transactions.
