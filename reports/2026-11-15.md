# 以太坊日报 2026-11-15

关键词：EIP-8500、后量子证明批处理、EIP-8151、ERC-8499、EIP-8037/8038 审计

摘要：周六整体安静，但后量子交易成本有了第一批实测数据：批量证明草案获分配编号 EIP-8500，作者 Marchhill 用实测建议把 leanSPHINCS 验证 gas 从 15,400 降到 3,000、leanSTARK 从 572,000 降到 30,000（均为临时值）。EIP-8151 的公共 mempool 规则获评审认可；ERC-8499 讨论转向助记词指纹设计。11-16 晚 ACDT #103 将公布 EIP-8037/8038 重新定价审计结论。

覆盖时间：约 2026-11-14 08:20 至 2026-11-15 08:20（Asia/Bangkok UTC+7）。文中时间均为 UTC+7。

## 今日要点
1. 后量子交易 Gas：批量证明草案改名为“Batched Generic Proof Dependencies”，编辑 abcoathup 分配编号 EIP-8500；作者发布实测，最坏情况的整块（16,384 个依赖）在全节点级机器上验证只需 22.5 ms，据此主张用上限而不是高 gas 来约束证明工作。
2. 账户抽象 mempool：EIP-8151 的“被恢复签名者”公共 mempool 规则获评审 colinlyguo 认可，并补充一条更强的安全理由：攻击者知道公钥就能构造恢复出目标地址的签名元组。
3. 钱包与助记词：ERC-8499 讨论建议助记词指纹从公钥计算，避免指纹被用来离线猜 passphrase；有状态密钥用随机叶子而不是计数器。
4. 本周会议：11-16 21:00 ACDT #103 公布 EIP-8037/8038 审计结论并选定 payload binding 方案；11-19 21:00 ACDE #249，11-26 21:00 ACDC #192 已建档。

## 重点话题

### 1. 后量子交易成本：EIP-8500 的实测与降价建议
**发生了什么**
- [EIP-8500 草案：Batched Generic Proof Dependencies](https://github.com/ethereum/EIPs/pull/12664) 2026-11-14 14:22 至 22:35 间，作者 Marchhill 连续提交 7 次修改，其中“把批处理简化为普通的通用依赖”“把 mempool 验证预算和 gas 校准分开”“区块依赖数量的上限独立于 gas limit”。2026-11-15 06:17 编辑 abcoathup 在评审里建议改为 eip: 8500，即分配了正式编号。
- 同一 PR 里作者的三条自评（2026-11-14 20:30、21:25，2026-11-15 02:55）：
  - 证明预算应拆成吞吐和延迟两部分。只有交易集确定后的最终聚合在关键路径上，在 GCP c3-highmem-22 上每层合并约 0.75 s，16 个 worker 处理满 60M 区块约 2.5 到 3.7 s。
  - 区块有效性只要求一份覆盖所有声明依赖的有效聚合证明；证明不出来的交易由 builder 自己舍弃，用优先费定价。所以协议只需要约束电路容量（MAX_DEPS_PER_BLOCK、MAX_INNER_PROOFS_PER_STEP）、FOCIL 下的强制工作量，以及 mempool 节点的验证成本。
  - 建议的临时 gas：LEANSPHINCS_VERIFICATION_GAS 3,000（现 15,400），LEANSTARK_VERIFICATION_GAS 30,000（现 572,000），RECURSIVE_PROOF_SHARE_GAS 约 2,700（现 5,100），LEANSTARK_LEAF_PAYMENT_GAS 约 35,000（现 675,000），LEANSTARK_CLAIM_GAS 约 500（现 4,200）。
  - 实测（n2-standard-8，EIP-7870 全节点级）：ecrecover 42.8 µs，leanSPHINCS 签名 0.39 ms，leanSTARK 叶子 11 到 16 ms，最坏整块 22.5 ms，约占 4 s 截止时间的 0.6%。容量方面，16,384 个依赖的完整证明在 c3-highmem-22 上 2.08 s 完成。每个叶子可容纳的签名数：ML-DSA-44 7 个，Falcon-512 30 个，SLH-DSA-SHAKE-128s 256 个。

**为什么重要**
- 后量子账户能不能日常使用，取决于每笔交易为签名验证付多少 gas。按现在的临时值，一次 leanSTARK 验证要 572,000 gas，约等于几十笔普通转账；作者的实测说明验证本身很便宜，大部分开销是“给 builder 证明能力配额”，而这部分可以交给优先费市场。
- 这是“用上限约束、gas 保持很小”的设计取向，会影响钱包估算 gas 的方式，也和 FOCIL 去留直接相关：强制包含列表里的交易要附带覆盖证明，builder 只做合并。
- 作者明确说两项验证 gas 仍是估计值，要实测 mempool 验证成本后才能固定，所以这些数字还不能当作最终参数。

**接下来关注**
- EIP-8500 的文件名与 Magicians 讨论帖更新，以及 [NethermindEth/lean-bindings #13](https://github.com/NethermindEth/lean-bindings/pull/13) 校准套件的完整数据。
- [EIP-8141 加入 leanSPHINCS 的 PR](https://github.com/ethereum/EIPs/pull/12616) 2026-11-15 03:33 仍有更新、未合并；Frame 交易用哪种后量子签名决定 EIP-8500 的实际负载。

### 2. 账户抽象：EIP-8151 mempool 规则和 EIP-7702 委托的可验证性
**发生了什么**
- [EIP-8151 公共 mempool 规则 PR 获评审认可](https://github.com/ethereum/EIPs/pull/12653) 2026-11-15 02:59 colinlyguo 留言建议补充理由：对“其他摘要”这一类，风险不只是签名重用；已知公钥时，若摘要由攻击者选择，可以构造一组 (digest, v, r, s) 恢复出目标地址而无需私钥。03:08 给出评审结论“lgtm，只补充理由”。PR 尚未合并。
- [EIP-8477（近期区块绑定的委托授权）讨论](https://ethereum-magicians.org/t/eip-8477-recent-block-bound-delegation-authorizations/30269) 2026-11-14 16:46 Helkomine 反对继续给 EIP-7702 加功能：7702 的目标是让 EOA 逐步过渡到智能账户，且 ECDSA 在后量子时代会被淘汰，继续加固它动力不足。
- [Magicians：如何验证已部署合约仍在运行审计过的代码](https://ethereum-magicians.org/t/checking-that-a-deployed-contract-still-runs-the-audited-commit/30318) 2026-11-14 22:17 thomasharris 指出 eth_getProof 可以证明某个 EIP-7702 账户在特定区块的 codeHash（即 0xef0100||address），但重新委托没有事件。2026-11-15 01:01 Zealynx 补充：同一区块内可以先换走再换回，按区块扫 codeHash 会漏掉；比较时段两端的 nonce 更可靠，因为每次生效的授权都会让 nonce 加一。

**为什么重要**
- EIP-8151 让 ecRecover 依赖被恢复地址的代码，节点必须知道哪些账户的变化会让 Frame 交易失效。评审补充的攻击方式说明，为“其他摘要”单独设配额是必要的。
- 对用 7702 委托的钱包和审计方，“nonce 两端相等就没有重新委托”是一个便宜可用的检查方法，可以直接写进监控脚本。

**接下来关注**
- 11-17 Frame Transaction Breakout #8（[pm #2295](https://github.com/ethereum/pm/issues/2295)）是否讨论 EIP-8151 合并。

### 3. 后量子钱包与 Gas 重新定价排期
**发生了什么**
- [ERC-8499 讨论：助记词指纹和有状态密钥](https://ethereum-magicians.org/t/erc-8499-hash-based-key-derivation-from-bip-39/30375) 2026-11-14 16:16 SergeevDmitry 确认作者已在恢复章节加入“旧密钥类型也要派生”；2026-11-15 01:04 Zealynx 建议固定指纹格式，并从公钥（例如账户 0 的 SLH-DSA-SHA2-128s 公钥）计算，类似 BIP-32 从主公钥取指纹；若直接从种子计算，拿到写有指纹的纸的人可以按 PBKDF2 速度离线猜 passphrase。对有状态密钥，他支持随机选叶子，因为设备复位或闪存回滚会让计数器重复。
- [ACDT #103 议程](https://github.com/ethereum/pm/issues/2299) 2026-11-14 16:30 更新：11-16 21:00 由 MariusVanDerWijden 介绍 EIP-8037/8038 现状，ChainSecurity 和 Dedaub 公布独立审计结论，EF 介绍内部调查和应用方沟通结果，其中列出 Juicebox 协议的兼容性 PoC；另一项是在两个 consensus-specs PR 中选定 payload binding 方案，以解锁共识规范发布。
- [ACDE #249](https://github.com/ethereum/pm/issues/2285) 11-19 21:00，议程 Glamsterdam、Hegotá；[ACDC #192](https://github.com/ethereum/pm/issues/2305) 2026-11-14 16:11 建档，11-26 21:00。

**为什么重要**
- 指纹设计看似细节，但会印在用户的备份纸上，设计不当就等于泄露 passphrase 的检验工具。
- EIP-8037/8038 会改变状态读写的 gas，Juicebox 被点名说明已部署合约确有兼容风险；ACDE #249 会据此决定改规格还是排期 Hoodi 测试网。

**接下来关注**
- 11-16 ACDT 审计结论中，受影响的合约类型和是否需要调整规格。
- 合约开发者可以先用 [glamsterdam-gas-invariants](https://github.com/ethereum/glamsterdam-gas-invariants) 对照自己的合约是否依赖可能改变的 gas 假设。
