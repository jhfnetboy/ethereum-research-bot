## 今日要点
1. **EOA 委托的“退出开关”开始和其他提案对齐**：EIP-8476（永久关闭 EIP-7702 委托）把账户代码设为 `0xef0200` 标记；今天提交的 EIP-8151 修订让这种账户仍能走 `ecrecover`，保证 ERC-2612 permit 不失效。
2. **Frame Transaction 修了一个 nonce 边界 bug**：发送方 nonce 只接受到 `MAX-1`，给本笔交易的 nonce 自增留出空间。这是破坏性变更，实现方需要自查。
3. **Ethlabs 第 19 周周报**：“7702 本身没坏”，原生 AA 是迁移到抗量子账户的基础，交易断言（transaction assertions）能给用户更多保障。
4. Devcon 8 前的 L1 R&D 研讨会今天开始，议题是 Hegotá 和 I*；Vitalik 抵达孟买。

## 重点话题

### 1. EIP-7702 委托的安全边界：永久退出与 permit 兼容
**发生了什么**
- [EIPs PR #12605：EIP-8151 把 0xef0200 退出标记视为合格 EOA](https://github.com/ethereum/EIPs/pull/12605) 16:01 提交。EIP-8151（Account Code Restricted ecRecover）目前只允许空代码或 `0xef0100 || delegate` 委托指示符的账户使用 `ecrecover`。如果和 EIP-8476 一起上线，选择退出 7702 的账户签的 permit 会返回空结果，与“只关闭委托能力、保留普通 EOA 能力”的本意矛盾。这个 PR 只把 EIP-8476 的标记加进合格集合。
- 背景：[EIPs PR #12600：Add EIP-8476 Permanent EOA Delegation Opt-Out](https://github.com/ethereum/EIPs/pull/12600)（2026-10-30 提交）。账户代码写成精确标记后，未来的授权（包括清除授权）都会被拒绝；EVM 把标记当作空代码处理（`EXTCODESIZE` 为 0，`EXTCODEHASH` 为空代码哈希）。
- [Ethlabs 第 19 周周报](https://ethlabs.org/updates/week-19.html) 18:33 发布，引用 Derek Chiang 10-30 的说明：7702 本身没有被攻破，使用支持 7702 的钱包（MetaMask、Uniswap、Ambire 等）不必恐慌。Barnabé 预期链上会出现更多由新账户能力承载、由 agent 管理的限速和熔断机制。

**为什么重要**
- Binance 事件让“EOA 一旦被委托就能被清空”的风险被放大。EIP-8476 给不想用 AA 的用户一个永久关门的选项，EIP-8151 的修订保证关门后 permit、签名登录这类基于 `ecrecover` 的流程不受影响。对钱包和 dapp 来说，判断“这个地址是不是普通 EOA”时要多认一个 `0xef0200` 标记。

**接下来关注**
- EIP-8476 和 EIP-8151 是否进入 Hegotá 讨论；钱包是否会提供“一键永久退出 7702”的入口。

### 2. EIP-8141 Frame Transaction：nonce 边界修复
**发生了什么**
- [EIPs PR #12603：Update EIP-8141 Transaction nonce check boundary](https://github.com/ethereum/EIPs/pull/12603) 18:20 合并。规范改为发送方 nonce 最大只接受 `MAX-1`，与 execution-specs 中 bogota 分叉的 frame transaction 实现一致。PR 标注为 Bugfix、Breaking Change、需要实现方 Action Required。

**为什么重要**
- EIP-8141 是原生账户抽象的主线提案（一笔交易拆成验证帧和执行帧，账户自己定义验证逻辑）。这类边界条件直接决定客户端之间是否一致，越早修越好。

**接下来关注**
- 客户端团队是否同步修复；Frame Transaction Breakout 的下一次会议安排。

### 3. 后量子：剑桥研讨会与 PQ PeerDAS
**发生了什么**

**为什么重要**
